# 인터뷰 04 — 10년 차 보안 컨설턴트

- 하는 일: 고객사 상주 보안 진단(보통 1~4주). 금융·공공·제조 고객이 많고, 외부 인터넷이 막힌 현장이 절반 이상
- 관리하는 레포: 공개 오픈소스 진단 도구 수십 개, 직접 만든 점검 스크립트, 체크리스트·보고서 템플릿
- 장비: 회사 지급 현장용 노트북(프로젝트마다 초기화), 사무실 준비용 개인 노트북, 업무 겸용 안드로이드 폰
- 확인한 화면: 01~18 전부

---

## 1. 지금의 작업 흐름

1. **출발 전 준비 (사무실, 인터넷 됨)**
   - 사무실 노트북에서 도구 레포들을 `git pull`로 최신화하고, 이번 고객 환경(OS 버전, 언어 런타임)에 맞는지 돌려 봅니다.
   - 쓸 버전을 정하면 커밋 해시를 메모해 두고, `git bundle create`로 레포별 번들을 만들어 암호화 USB에 담습니다. 파이썬 의존성은 오프라인 설치용 패키지로 같이 챙깁니다.
   - 고객사 반입 절차가 있어서 USB 목록·해시값을 반입 신청서에 적어 냅니다.
2. **현장 (대부분 외부망 차단)**
   - 반입 검사를 받은 USB에서 현장 노트북으로 번들을 clone합니다.
   - 현장에서 스크립트를 고치는 일이 꽤 많습니다(고객 환경에 맞춘 예외 처리 등). 그건 현장 노트북의 로컬 브랜치에 커밋해 둡니다.
   - 폰은 보안 구역 입구에서 카메라 봉인 스티커를 붙이거나 아예 보관함에 맡깁니다. 고객 망에 개인 기기를 붙이는 건 계약상 금지인 곳이 대부분입니다.
3. **철수 후 (사무실)**
   - 현장에서 고친 스크립트 변경분만 골라서 공용 레포에 반영합니다. 고객 이름·IP·계정 같은 게 섞여 있지 않은지 diff를 한 줄씩 봅니다.
   - 현장 노트북과 USB는 정해진 절차로 초기화하고, 초기화 확인서를 냅니다.
4. **평소 업데이트**
   - 원본 도구가 갑자기 저장소째 사라지거나, 작성자가 히스토리를 갈아엎는 경우가 실제로 있습니다. 그래서 중요한 건 사내 Gitea에 pull 미러로 걸어 둡니다.

## 2. 단계별 불편과 바라는 점

| 단계 | 불편 | 있었으면 하는 것 |
|---|---|---|
| 준비 | 레포 수십 개를 하나씩 pull하고 번들 만드는 게 반나절 일 | 레포를 묶어서 "이번 프로젝트 키트"로 고정하고, 한 번에 번들로 내보내기 |
| 준비 | 원본 업데이트를 그냥 받아도 되는지 불안함. 공급망 공격 사례가 계속 나옴 | 업데이트를 바로 반영하지 않고 "대기"시킨 뒤, 무엇이 바뀌었는지 보고 승인하는 모드 |
| 준비 | 도구 다수가 서브모듈을 쓰거나, 실제로 쓰는 건 릴리스 첨부 파일인 경우가 많음 | 서브모듈과 릴리스 파일까지 같이 보존 |
| 현장 | 현장에선 폰을 못 쓰는 경우가 대부분 | 현장용이 아니라 "준비·보관용"이라는 걸 전제로 설계해도 충분 |
| 철수 후 | 현장 변경분에 고객 정보가 섞이는 사고가 가장 무서움 | 프로젝트 단위로 레포를 분리하고, 끝나면 한 번에 안전 삭제 + 삭제 기록 |
| 평소 | 원본 삭제·강제 push를 나중에야 알게 됨 | 원본이 사라지거나 히스토리가 바뀌면 바로 알림, 이전 기록은 자동 보존 |

## 3. 화면을 보고 든 생각

### 바로 쓸 수 있을 것 같은 부분
- **03-add-mirror**: 등록 전에 "브랜치·태그 26개 받기 · PR 브랜치 34개 제외"를 미리 보여 주는 게 좋습니다. 여러 줄 붙여넣기도 실무적입니다.
- **05-bulk-mirror**: 특정 조직의 레포를 통째로 따라갈 때 유용합니다. "포크 숨기기", 이미 등록된 레포 표시, 선택 용량 합계까지 다 필요한 정보입니다.
- **06-repo-detail-mirror**: 미러는 읽기 전용이고 고치려면 "분리하기"라는 구분이 명확합니다. 원본을 실수로 오염시킬 일이 없어 마음에 듭니다.
- **08-push-history**: push마다 경로(와이파이), 보낸 IP, 이전→이후 해시가 남습니다. 저한테는 감사 로그로 쓸 수 있는 수준입니다.
- **07-repo-detail-local**: "내보내기 — git bundle"이 있는 게 결정적입니다. 지금 제 흐름이 번들 기반이라 그대로 이어집니다.
- **09-qr**: "주소에는 계정 정보가 들어가지 않아요" 문구가 좋습니다. 보안하는 사람은 이런 걸 꼭 확인합니다.
- **10-settings**: "연결 경로별 보안"에서 와이파이가 암호화되지 않는다고 솔직하게 써 둔 점은 신뢰가 갑니다.
- **15-web-repo-home**: "보존된 기록 0개"가 보이는 게 좋습니다. 이 숫자가 늘면 원본에서 무슨 일이 있었다는 신호로 쓰겠습니다.

### 빠져 있거나 헷갈리는 부분
- **03 / 06**: 원본 업데이트를 자동으로 반영만 하고 "검토 후 반영" 선택지가 안 보입니다. 저한테는 가장 중요한 기능입니다.
- **06**: "동기화 이력 2" 탭에서 원본이 강제 push했을 때 어떻게 보이는지 궁금합니다. "업데이트 1분 전"만으로는 정상 업데이트인지 히스토리 재작성인지 구분이 안 됩니다. 메인 목록(**01**)에도 경고 배지가 있었으면 합니다.
- **03**: "원본 접속 토큰" 드롭다운이 있는데, 토큰이 폰 어디에 어떻게 저장되는지(안드로이드 키스토어인지) 설명이 없습니다.
- **07**: 내보내기 번들이 암호화되는지, 어디에 저장되는지 보이지 않습니다. **11-storage**의 "전체 백업 (zip)"도 마찬가지입니다. 평문 zip이 다운로드 폴더에 떨어지면 다른 앱이 읽을 수 있습니다.
- **02-add-sheet**: "PC 프로젝트 올리기"와 "빈 레포 만들기"가 거의 같은 일이라 헷갈립니다. 하나로 합쳐도 됩니다.
- **14~17 웹 화면**: 레포 이름·설명 검색만 있고, 레포 전체 코드 검색이 없습니다. "그 스크립트 어느 레포에 있었지"가 제일 자주 하는 질문입니다.
- 레포를 프로젝트(고객)별로 묶는 태그나 폴더가 없습니다. **01**의 "client-a" 같은 이름만으로 구분하는 건 금방 한계가 옵니다.

### 불안해 보이는 부분
- **01-main / 13-main-dark**: 메인 화면 맨 위에 사설 IP와 포트가 크게 노출됩니다. 화면 공유나 어깨너머로 쉽게 보입니다. 숨김 옵션이 있었으면 합니다.
- **04-pc-upload-guide / 06**: "사용자 이름 git, 비밀번호는 이 앱의 비밀번호"를 PC git에 넣으라고 안내하는데, PC의 자격 증명 관리자가 그걸 저장합니다. 고객사 PC나 공용 PC에서 쓰면 폰 비밀번호가 남습니다. 레포별·기기별로 발급하고 회수할 수 있는 토큰 방식이 필요합니다.
- **10-settings**: "비밀번호 요구"에 "끄기"가 있고 그 아래에 ngrok이 있습니다. 비밀번호를 끈 상태에서 ngrok을 켜면 인터넷 전체에 레포가 열립니다. 이 조합은 아예 막거나, 최소한 강한 경고를 띄워야 합니다.
- **10-settings**: 와이파이 경로가 평문 HTTP인데 대안이 Tailscale뿐입니다. 자체 서명 인증서로 HTTPS를 켜고 지문(fingerprint)을 화면에 보여 주는 정도는 있었으면 합니다.
- 앱 자체 잠금(생체 인증, PIN)이 어느 화면에도 안 보입니다. 폰을 잠깐 빌려주거나 잃어버렸을 때 레포가 그대로 열립니다.
- **10-settings**: "부팅 후 서버 자동 시작"은 제 입장에선 기본 꺼짐이 맞고, 실제로 꺼져 있어 다행입니다. 오히려 "N시간 뒤 서버 자동 종료"가 있었으면 합니다.

## 4. 비교·참고할 만한 제품

| 제품 | 좋은 점 | 아쉬운 점 |
|---|---|---|
| Gitea / Forgejo (사내 서버, NAS) | pull 미러 주기 설정, 사용자·권한, 웹 UI가 성숙함 | 서버를 따로 운영해야 하고 들고 다닐 수 없음. 원본 히스토리 재작성 시 이전 기록 보존은 기본 동작이 아님 |
| `git bundle` + 암호화 USB | 오프라인 반입 절차와 잘 맞고, 해시로 무결성 확인 가능 | 전부 수작업. 레포가 많으면 스크립트로 버팀 |
| 조직 단위 일괄 clone CLI 도구 (예: ghorg) | 계정·조직 전체를 한 번에 받음 | 받기만 하고 보존·이력·서빙은 없음 |
| Termux + git (폰) | 폰에서 git을 그대로 씀 | 서버·백그라운드 유지·UI 모두 직접 해야 함 |
| Syncthing | 기기 간 동기화가 매끄러움 | git 히스토리를 이해하지 못해 충돌 시 파일이 깨짐 |
| Software Heritage | 공개 레포의 장기 보존 | 공개 서비스라 비공개 도구·사내 스크립트는 못 맡김, 오프라인 사용 불가 |

mobilegit은 "Gitea의 미러 + 번들 내보내기 + 보존"을 주머니에 넣은 형태라는 점이 새롭습니다.

## 5. 꼭 더해졌으면 하는 것 3가지 / 없어도 되는 것

**꼭 더해졌으면 하는 것**
1. **업데이트 검토 모드와 원본 변경 알림**: 원본 업데이트를 대기시키고 diff를 본 뒤 승인. 강제 push·저장소 삭제·태그 이동은 즉시 알림.
2. **저장 데이터 보호**: 앱 잠금, 레포 저장소 암호화, 내보내기·백업 파일 암호화, 프로젝트 단위 안전 삭제(삭제 기록 포함), 기기별로 발급·회수하는 접속 토큰.
3. **프로젝트 키트 내보내기**: 레포 여러 개를 특정 커밋으로 고정해 한 번에 번들로 내보내고, 각 번들의 해시 목록을 같이 만들어 주기. 서브모듈과 릴리스 파일 포함.

**없어도 되는 것**
- **09-qr**의 "다른 폰이나 태블릿 카메라로 찍기" 용도: 제 흐름에선 쓸 일이 거의 없습니다. 복사 버튼이면 충분합니다.
- **02-add-sheet**의 "빈 레포 만들기": "PC 프로젝트 올리기"와 합쳐도 됩니다.
- ngrok 경로: 저는 쓰지 않을 겁니다. 남긴다면 설정 깊숙이 넣고 기본 꺼짐, 비밀번호 필수로 고정해 주세요.

## 6. 그 외에 하고 싶은 말

- 저 같은 사람에게 이 앱은 "현장에서 쓰는 서버"가 아니라 "출발 전 준비와 평소 보관을 맡는 금고"입니다. 고객 망에 폰을 붙이는 일은 없을 겁니다. 그 전제로 보면 보존·검토·내보내기가 핵심이고, 접속 경로 다양화는 덜 중요합니다.
- 화면 문구가 솔직해서 좋습니다(**10**의 경로별 보안 설명). 다만 위험한 조합(비밀번호 끄기 + 외부 공개)은 문구가 아니라 동작으로 막아 주세요. 보안 담당자가 회사에서 이 앱 사용을 허락할지 말지는 거기서 갈립니다.
- 회사에서 쓰려면 "이 앱이 외부로 무엇을 보내는지"를 한 장으로 정리한 문서가 필요합니다. 텔레메트리 여부, 어떤 주소로 통신하는지, 데이터가 어디 저장되는지. 그게 있으면 내부 승인 받기가 훨씬 쉽습니다.
