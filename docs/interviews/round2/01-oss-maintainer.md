## 1. 지금 백업·업스트림 보관을 어떻게 하고 있나

순서대로 말하면 이렇습니다.

1. **목록 관리**: 홈 서버(집에 있는 미니 PC, Ubuntu)에 `upstreams.txt`가 있어요. 한 줄에 URL 하나. 새 의존성을 넣을 때마다 손으로 추가합니다. 솔직히 절반은 까먹어요. lockfile에는 있는데 목록에는 없는 게 늘 있습니다.
2. **미러 받기**: `git clone --mirror`로 받습니다. 처음엔 bash 스크립트였고 지금은 그냥 cron이 6시간마다 `git remote update --prune`을 돌려요.
3. **히스토리 재작성 대비**: 이게 핵심인데, `--prune`과 force 업데이트를 그대로 받으면 미러가 원본을 따라 망가집니다. 그래서 cron 직전에 `refs/*`를 `refs/archive/<날짜>/*`로 복사해 두는 스크립트를 따로 붙였어요. 날짜별 ref가 쌓이니 `git gc`가 옛 커밋을 안 지웁니다. 대신 ref가 수천 개로 불어나서 가끔 손으로 정리해요.
4. **변화 감지**: 업데이트 전후 `git for-each-ref` 결과를 diff해서, 기존 ref가 조상 관계가 아닌 커밋으로 바뀌었으면(=force-push) 텔레그램 봇으로 알림을 보냅니다. 원본이 404가 되면 fetch가 실패하니까 그것도 알림.
5. **릴리스 산출물**: 태그만으로는 부족해서 중요한 의존성은 npm tarball도 따로 받아 둡니다. GitHub Releases의 바이너리는 거의 못 챙기고 있어요.
6. **오프사이트 사본**: 월 1회 `git bundle create --all`로 묶어서 외장 SSD + 클라우드(Backblaze B2)에 올립니다.
7. **내 레포 백업**: 내가 관리하는 두 라이브러리는 GitHub 외에 Codeberg와 자체 Gitea에 push 미러를 걸어 둡니다. 이슈·PR·위키는 `gh` CLI로 가끔 JSON 덤프만.

## 2. 단계별 불편과 원하는 것

| 단계 | 불편 | 있었으면 하는 것 |
|---|---|---|
| 목록 관리 | 의존성 목록과 미러 목록이 따로 놀아요. lockfile에 새로 들어온 패키지를 놓칩니다. | `package.json`/lockfile(나아가 `go.mod`, `Cargo.lock`)을 넣으면 각 패키지의 저장소 URL을 뽑아 일괄 등록 후보로 보여 주기 |
| 미러 받기 | 홈 서버가 꺼지거나 디스크가 차면 며칠씩 조용히 멈춰 있어요. 멈춘 걸 모르는 게 제일 무섭습니다. | "마지막 성공 동기화"가 오래된 레포를 눈에 띄게 경고 |
| 히스토리 보존 | 직접 짠 스크립트라 저만 알아요. 복원할 때 어느 날짜 ref를 봐야 하는지 매번 헤맵니다. | force-push 감지 시 이전 tip을 자동 보존하고 "언제, 어떤 ref가, 어디서 어디로" 바뀌었는지 목록으로 |
| 변화 감지 | 텔레그램 알림이 6시간 cron에 묶여 있어 늦어요. 그리고 "원본 삭제"와 "일시적 네트워크 오류"를 구분 못 해서 오탐이 잦아요. | 원본 상태를 "정상 / 접근 실패(일시) / 404 지속(삭제 추정) / 비공개 전환"으로 구분 |
| 릴리스 산출물 | 태그 이동(같은 이름 태그를 다른 커밋에 다시 찍기)을 사람이 눈치채기 어렵습니다. | 태그 이동은 별도 경고. 이게 공급망 사고의 전형이에요 |
| 오프사이트 사본 | bundle 만들고 올리는 걸 자꾸 미룹니다. | 주기적 bundle 내보내기를 SAF 폴더(구글 드라이브, USB 등)로 자동 |

## 3. 스크린샷 평가

### 바로 쓸 수 있을 것 같은 부분

- **03-add-mirror.png**: 여러 줄 붙여넣기, 등록 전에 "접근 가능 · 브랜치·태그 26개 · PR 브랜치 34개 제외"를 미리 보여 주는 거 좋아요. PR ref를 기본 제외한 건 옳은 판단입니다. 제 홈 서버 미러가 `refs/pull/*` 때문에 몇 배로 커진 적이 있어요. "이 폰 주소"를 미리 보여 주는 것도 좋습니다.
- **05-bulk-mirror.png**: 조직 일괄 미러에 "포크 숨기기", "보관된 레포 숨기기", 이미 등록된 건 "등록됨" 표시, 선택 용량 합계까지. sindresorhus 같은 계정을 통째로 따라가는 데 바로 쓰겠어요.
- **06-repo-detail-mirror.png**: clone 명령 복사, "지금 업데이트", 읽기 전용이라 push 거부, "분리하기"까지 흐름이 명확합니다. 업스트림이 죽었을 때 포크해서 내가 이어받는 시나리오가 "분리하기"로 이어지는 게 좋아요.
- **11-storage.png**: 최소 여유 공간 아래면 자동 업데이트를 멈춘다는 정책이 명시돼 있어 안심됩니다. "전체 백업(zip)"도 오프사이트 사본 용도로 바로 씁니다.
- **14~17 웹 화면**: GitHub와 거의 같은 구조라 학습 비용이 없어요. 16-web-file-view의 "이 파일의 커밋", 파일 다운로드가 원본이 사라졌을 때 특정 파일을 꺼내는 데 딱 필요합니다.
- **10-settings.png**: 연결 경로별 보안(와이파이 평문, Tailscale 안전, ngrok 공개)을 솔직하게 써 둔 게 좋습니다. 저는 ngrok는 안 켤 것 같아요.

### 빠져 있거나 헷갈리는 부분

1. **이 앱의 핵심인 "보존"이 화면에 안 보입니다.** 15-web-repo-home.png 정보 박스에 "보존된 기록 0개"가 한 줄 있는 게 전부예요. 이게 뭘 세는 건지, 0이 아닐 때 어디서 보는지 18장 어디에도 없습니다. force-push 전 tip, 사라진 브랜치, 이동된 태그를 보여 주는 화면이 제일 먼저 필요해요.
2. **06-repo-detail-mirror.png의 "동기화 이력 2" 탭 내용을 못 봤어요.** 08-push-history.png(로컬 레포)처럼 `main a → b` 형식이면 좋겠는데, 미러에서는 "fast-forward 아님(히스토리 재작성)", "브랜치 삭제됨", "태그 이동" 같은 이벤트가 색으로 구분돼야 합니다.
3. **01-main.png 레포 목록에 원본 상태가 없어요.** "미러 · 업데이트 1분 전"만 보이는데, 원본이 404거나 force-push가 감지된 레포는 목록에서 바로 튀어야 합니다. 필터 칩도 "전체/미러/로컬" 말고 "주의 필요"가 있으면 좋겠어요.
4. **업데이트 주기 설정이 안 보입니다.** 10-settings.png에도 03-add-mirror.png의 "고급"(접혀 있음)에도 주기가 보이지 않아요. 레포별로 다르게(핵심 의존성은 1시간, 나머지는 하루) 줄 수 있어야 합니다. 배터리 경고(01)가 있는 걸 보면 주기가 배터리와 직결될 텐데 그게 사용자에게 안 보입니다.
5. **알림 설정이 없어요.** 업스트림이 사라지거나 히스토리가 바뀌면 폰 알림이 와야 하는데, 설정 화면에 그런 항목이 없습니다. 폰에서 돌아가는 앱의 가장 큰 장점이 바로 푸시 알림인데요.
6. **15-web-repo-home.png "브랜치 · 태그 1 · 46"**: 03에서는 "브랜치·태그 26개"라고 했는데 chalk는 46개 태그. 숫자는 맞을 수 있지만, 미러가 받는 ref 범위(브랜치 전부? 태그 전부? notes?)가 어디에도 명시돼 있지 않아요. 고급 옵션에 ref 범위를 보여 주세요.
7. **웹 커밋 화면(17)에 미러 레포의 "보존된 옛 히스토리"로 갈 길이 없어요.** 브랜치 드롭다운(main)에 보존 ref가 같이 나오는지, 따로 나오는지 궁금합니다.
8. **07-repo-detail-local.png "내보내기"는 로컬 레포에만 보여요.** 미러야말로 bundle 내보내기가 필요합니다(원본이 사라졌을 때 다른 데 다시 올리려고).
9. **사소한 것**: 05-bulk-mirror.png "전체 선택"이 두 줄로 깨집니다. 11-storage.png "레포 용량은 2시간 전 기준"은 좋은데 새로고침 버튼과의 관계가 헷갈려요.

## 5. 꼭 더해졌으면 하는 3가지 / 없어도 되는 것

**꼭 더해졌으면 하는 것**

1. **보존 기록 화면 + 이벤트 분류**: force-push(비 fast-forward), 브랜치 삭제, 태그 이동, 원본 삭제·비공개 전환을 감지해 이전 상태를 ref로 보존하고, 레포 상세와 웹 양쪽에서 "보존된 기록"으로 열람·clone할 수 있게. 이게 없으면 그냥 미러 앱이에요.
2. **이상 징후 알림 + 목록 상태 배지**: 위 이벤트가 생기면 안드로이드 알림, 메인 목록에 "주의 필요" 필터. "동기화가 N일째 실패" 경고도 같이.
3. **의존성 파일에서 일괄 등록**: `package.json`/lockfile을 붙여넣거나 PC에서 올리면 저장소 URL을 뽑아 05-bulk-mirror.png 같은 선택 화면으로. 메인테이너가 미러하는 대상은 "계정"보다 "내 의존성 트리"입니다.

(덤으로 하나 더 고르라면 레포별 업데이트 주기와 미러 bundle 내보내기.)

**없어도 되는 것**

- **04-pc-upload-guide.png의 VS Code 안내 문구**: 이 앱 쓰는 사람은 `git remote add`를 압니다. 공간만 차지해요.
- **09-qr.png의 큰 QR 화면**: PC에서 clone하는데 QR은 거의 안 씁니다. 다른 폰으로 주소를 넘길 일도 드물고요. 01 상단 서버 카드의 QR 아이콘 하나면 충분해요.
- **ngrok 경로**: 저라면 Tailscale만 씁니다. 공개 주소에 보관소를 노출하는 건 메인테이너 입장에서 꺼려져요. 지우라는 건 아니고 기본값에서 숨겨도 됩니다.
- **13/18 다크 모드**는 잘 돼 있는데 우선순위 논의 대상은 아니에요(있으면 좋고 없어도 됨).

## 6. 그 외

- **폰이 서버라는 점의 신뢰도**가 결국 관건이에요. 01의 배터리 최적화 경고를 보니 팀도 알고 있는 것 같은데, "지난 24시간 동안 예정된 업데이트 중 몇 번 실제로 돌았는지" 같은 건강 지표가 보이면 믿고 맡길 수 있겠어요.
- 보존은 "지우지 않는 것"이라 용량이 단조 증가합니다. 11-storage.png에 보존 기록이 차지하는 용량을 따로 보여 주고, 지울 때는 레포 단위로 신중하게(되돌릴 수 없다고 명확히) 해 주세요.
- 업스트림 삭제 사고 때 실제로 필요했던 건 "그 시점에 내가 쓰던 태그의 정확한 커밋"이었어요. 태그 → 커밋 해시 매핑이 바뀐 이력을 남겨 주면 공급망 사고 조사할 때 엄청 도움이 됩니다.
- 이슈·PR·릴리스 첨부까지 바라진 않아요. git 데이터만 확실히 지켜 주는 쪽이 낫습니다. 범위를 넓히다 핵심이 흐려지는 걸 많이 봤어요.
