# 인터뷰 05 — 1인 인디 게임 개발자 (Unity, 경력 7년)

- 페르소나: 혼자 Unity로 PC/모바일 게임을 만든다. 현재 프로젝트는 2D 액션 로그라이트로, 개발 3년째에 출시 준비 중이다.
- 기기: 집 데스크톱(Windows, RTX 그래픽카드, 2TB NVMe), 노트북(Windows, 512GB), 폰은 갤럭시(256GB, 남은 공간 약 120GB)
- 도구: Unity 2022 LTS, Rider, GitHub(private) + Git LFS, Fork(git GUI), 외장 SSD 1TB, Google Drive 2TB
- 본 화면: 01~18 전부

---

## 1. 지금 코드와 에셋을 여러 기기에서 관리·백업하는 방법

순서대로 쓰면 이렇습니다.

1. **집 데스크톱에서 주 작업.** Unity 프로젝트 루트가 git 레포입니다. `.gitignore`로 `Library/`, `Temp/`, `Builds/`는 빼고, `.gitattributes`로 `*.psd`, `*.png`, `*.wav`, `*.fbx`, `*.aseprite` 같은 걸 LFS로 걸어 둡니다. 작업 폴더 전체는 18GB 정도인데 레포로 들어가는 건 6GB쯤이고, 그중 5GB 넘게가 LFS 객체입니다.
2. **커밋·push는 Fork로.** 하루 일 끝나면 `origin`(GitHub private)으로 push합니다. LFS 대역폭/저장 한도가 계속 문제라 데이터 팩을 두 번 샀어요. 한 달에 5달러씩이 쌓이는 게 1인 개발자한텐 꽤 아픕니다.
3. **노트북으로 이동.** 카페나 본가에 갈 때 노트북에서 `git pull` + `git lfs pull`. 노트북은 용량이 작아서 `lfs.fetchexclude`로 원본 PSD 폴더는 안 받게 해 놨습니다. 그런데 가끔 그 설정을 까먹고 다 받아서 디스크가 꽉 찹니다.
4. **원본 아트·사운드 소스는 따로.** 작곡가랑 외주 아티스트한테 받는 원본(멀티트랙 오디오, 레이어 PSD 수 GB)은 git에 안 넣고 Google Drive 폴더로 공유합니다. 그래서 "이 커밋 시점에 쓰던 원본이 뭐였지"가 끊어집니다.
5. **빌드 보관.** 스팀 업로드용 빌드는 `Builds/` 아래 날짜 폴더로 만들어서 외장 SSD에 손으로 복사합니다. 마일스톤 때만 `v0.8.3` 같은 태그를 답니다.
6. **주 1회 백업.** 외장 SSD에 프로젝트 폴더 통째로 robocopy. 이것도 기억날 때만 해요.

**출시 직전 빌드 기록을 잃어버린 일:** 데모 버전 출시 직전에 노트북에서 급하게 핫픽스를 했는데, 데스크톱 쪽 브랜치랑 꼬여서 `push --force`를 했습니다. 그 바람에 스팀 넥스트 페스트에 올렸던 빌드가 어느 커밋에서 나왔는지 기록이 날아갔어요. 태그도 안 달았고 reflog는 다른 기기에 있었고요. 플레이어가 "데모 버전에서는 됐는데 지금은 안 돼요"라고 버그 리포트를 줬는데, 그 빌드를 다시 만들 수가 없어서 이틀을 버렸습니다.

## 2. 단계별로 불편한 점과 있었으면 하는 기능

| 단계 | 불편한 점 | 있었으면 하는 것 |
|---|---|---|
| LFS 설정/push | GitHub LFS 요금과 한도. 한도를 넘으면 push가 막혀서 출시 주간에 패닉이 옴 | 용량 걱정 없이 LFS 객체를 받아 주는 내 소유 원격 저장소 |
| 기기 이동 | 노트북에서 매번 `git lfs pull`이 느리고 디스크를 많이 먹음 | 같은 와이파이면 빠르게 받기, 필요한 LFS만 받기 |
| 외주 원본 | Drive와 git이 따로 놀아서 시점을 맞출 수 없음 | (git 밖의 일이라 앱에 바라진 않음) |
| 빌드 보관 | 빌드 zip과 커밋이 연결되어 있지 않음 | "이 태그 = 이 빌드 파일" 연결, 최소한 태그/커밋이 절대 안 사라지는 것 |
| force push | 히스토리를 덮어쓰면 GitHub에선 복구가 사실상 안 됨 | 덮어쓰기 전 상태를 자동으로 남겨 두는 백업 원격 |
| 정기 백업 | 수동이라 빼먹음 | 신경 안 써도 계속 돌아가는 2차 사본 |

## 3. 스크린샷이 내 작업 흐름에 맞는지

결론부터: **"force push로 날린 기록을 보존한다"는 개념은 저한테 정확히 필요한 거예요.** 그런데 화면만 봐서는 **Unity 프로젝트를 올릴 수 있는지(LFS, 수 GB 레포)가 전혀 안 보여서** 바로 믿고 쓰긴 어렵습니다. 화면에 나온 레포가 전부 몇 KB~1MB짜리라 더 그래요.

### 바로 쓸 수 있을 것 같은 부분

- **04-pc-upload-guide**: `git remote add phone ...` + `git push -u phone main` 두 줄이면 끝난다는 게 좋습니다. 저는 origin은 GitHub 그대로 두고 `phone`을 두 번째 원격으로 붙이는 식으로 쓸 것 같아요. 원격 이름을 `phone`으로 정해 준 것도 센스 있습니다.
- **08-push-history**: 어느 브랜치가 어떤 해시에서 어떤 해시로 갔는지, 어느 IP(=어느 기기)에서 왔는지 남는 게 딱 제가 잃어버렸던 정보입니다. 데스크톱(.101)이랑 노트북을 구분할 수 있으면 "누가 force push했나"를 바로 알 수 있겠네요.
- **06-repo-detail-mirror / 15-web-repo-home**의 "보존된 기록 0개": 원본 히스토리가 바뀌면 여기 숫자가 올라가는 거라면 정말 좋습니다. 다만 로컬 레포(07)에는 이 항목이 안 보여요. 저한테는 미러보다 **로컬 레포에 force push가 들어왔을 때의 보존**이 더 중요합니다.
- **07-repo-detail-local**의 "내보내기 (git bundle 또는 소스 zip)": 외장 SSD로 옮길 때 bundle 하나로 떨어지는 건 좋습니다.
- **11-storage**: 레포별 용량을 큰 순으로 보여 주고, "최소 여유 공간 1.0GB"에서 멈추는 안전장치가 있는 건 마음에 듭니다. 폰이 꽉 차서 카톡도 안 되는 상황은 막아 줄 테니까요.
- **17-web-commit-log**: 노트북에서 "어제 데스크톱에서 뭘 커밋했더라" 확인하기 좋습니다.

### 빠져 있거나 헷갈리는 부분

1. **LFS 지원 여부가 어디에도 없음 (04, 07, 10, 11 전부).** 제일 큰 문제입니다. `git push phone main` 했을 때 LFS 객체가 같이 가는지, 아니면 포인터 파일만 가서 나중에 clone하면 텍스처가 다 깨지는지 알 수 없어요. 04 안내에 "LFS를 쓰는 레포는 `git lfs push phone --all`도 하세요" 같은 한 줄이나, 07 정보 카드에 "LFS 객체 1,240개 · 5.3GB" 같은 표시가 꼭 있어야 합니다.
2. **큰 첫 push의 진행 상황.** 6GB를 와이파이로 처음 올리면 수십 분 걸릴 텐데, 그동안 폰 화면에서 받는 중인지, 화면이 꺼져서 끊긴 건지 알 수 있는 표시가 없어요. 01의 배터리 최적화 경고가 바로 이 걱정을 하게 만듭니다. "push 받는 중 2.1GB / 6GB" 같은 진행 알림이 필요합니다.
3. **03-add-mirror에서 GitHub private 레포를 LFS 포함으로 미러할 수 있는지.** "원본 접속 토큰(비공개 레포만)"은 있는데, 미러가 LFS 객체까지 받는지는 안 나옵니다. GitHub에서 LFS를 받으면 그것도 대역폭 한도를 먹으니까 "LFS 받기: 켜기/끄기" 옵션이 고급(03 하단)에 있어야 할 것 같아요.
4. **11-storage의 "mobilegit이 쓰는 공간 4.2MB" 숫자 감각.** 제 레포 하나만 6GB라서, 폰에 몇 개 버전까지 쌓일지 예상을 하고 싶어요. 레포별로 "보존 기록이 차지하는 용량"이 따로 보이면 좋겠습니다.
5. **06 "분리하기"의 의미.** 미러를 로컬 레포로 바꾼다는 건 알겠는데, 분리하면 원본 추적이 끊기는 건지, 보존 기록은 남는 건지가 확실하지 않아요.
6. **태그가 화면에 거의 없음.** 15에는 "브랜치·태그 1·46"이 숫자로만 있고, 14/15/17 어디에도 태그 목록이나 태그 기준 탐색이 안 보여요. 저한텐 `v0.8.3-nextfest` 같은 태그가 커밋보다 중요한 단위입니다.
7. **16-web-file-view에서 바이너리 에셋.** 코드 보기는 좋은데, `.png`나 `.prefab`, `.unity` 씬 파일을 열면 어떻게 보이는지 궁금합니다. 이미지 정도는 미리보기가 되면 좋겠고, LFS 포인터 파일이 텍스트로 그냥 보이면 헷갈릴 거예요.
8. **10-settings의 와이파이 비암호화 경고.** 집 와이파이라 크게 신경은 안 쓰지만, 카페에서 노트북으로 붙을 때는 Tailscale을 쓰라는 안내를 상황에 맞게(지금 공용 와이파이인지) 해 주면 좋겠어요. 지금은 설정 깊숙이 있어서 안 읽을 것 같습니다.

## 4. 비교·참고할 만한 제품

| 제품 | 좋은 점 | 아쉬운 점 |
|---|---|---|
| **GitHub + Git LFS** | 다들 쓰고, Actions로 빌드 자동화 가능 | LFS 요금·한도. force push로 날린 커밋은 복구가 사실상 불가능 |
| **Unity Version Control (Plastic SCM)** | 큰 바이너리에 강하고 Unity랑 붙어 있음 | 무료 한도를 넘으면 요금, 클라우드 종속, git이 아니라 다른 도구들과 안 맞음 |
| **Gitea / Forgejo (집 NAS나 라즈베리파이)** | LFS 지원, 웹 UI, 무료 | NAS를 사고 관리해야 함. 밖에서 접속하려면 포트포워딩이나 Tailscale 직접 설정 |
| **Perforce Helix Core** | 게임 업계 표준, 대용량 바이너리 최강 | 1인 개발자한테는 과함. 설치·관리가 무거움 |
| **Syncthing** | 기기 간 폴더 동기화가 편하고 무료 | 버전 관리가 아니라서 Unity `Library/`까지 꼬이면 지옥. 히스토리 없음 |
| **Google Drive / 외장 SSD** | 그냥 복사하면 됨 | 버전과 커밋이 연결 안 됨. 수동이라 빼먹음 |

mobilegit은 "Gitea를 NAS 없이 폰으로" 쯤에 위치한다고 느꼈어요. 서랍에 굴러다니는 옛날 폰(갤럭시 S20, 128GB)을 서버로 쓰면 딱이겠다는 생각이 바로 들었습니다. 다만 Gitea와 비교하면 LFS가 되는지가 승부처입니다.

## 5. 꼭 더해졌으면 하는 것 3가지 / 없어도 되는 것

### 꼭 필요한 것

1. **Git LFS 서버 지원 + 화면 표시.** push/clone 시 LFS 객체를 받고 내주는 것, 그리고 07/11에서 LFS 용량을 따로 보여 주는 것. 이게 없으면 게임 개발자에겐 의미가 없습니다.
2. **로컬 레포의 force push 보존과 태그 보호.** 미러처럼 로컬 레포에도 "덮어쓰기 전 기록" 보존이 되고, 태그는 삭제나 이동을 해도 이전 기록이 남는 것. 08 push 이력에 "강제 덮어쓰기" 배지와 "이 시점으로 되살리기" 버튼이 있으면 완벽합니다.
3. **큰 전송의 진행 상황과 끊김 안전성.** 수 GB push 중 진행률 알림, 중간에 끊겼을 때 이어받기(또는 최소한 레포가 깨지지 않는다는 보장).

(하나 더 고르자면) 태그나 커밋에 빌드 zip을 붙여 두는 "릴리스 첨부" 기능. GitHub Releases의 개인판 같은 거요.

### 없어도 되는 것

- **05-bulk-mirror(계정·조직 일괄 미러)**: 저는 제 레포 2~3개만 관리해서 쓸 일이 없어요. 오픈소스 많이 보는 사람한텐 좋겠지만 저한텐 우선순위가 낮습니다.
- **09-qr의 "다른 폰이나 태블릿 카메라로 찍기"**: PC에서 clone하는 게 목적이라 QR은 거의 안 쓸 것 같습니다. 복사 버튼이면 충분해요.
- **14~16 웹 코드 보기**: 있으면 좋지만 저는 Rider로 보니까 핵심은 아닙니다. 17 커밋 로그는 쓸 것 같아요.

## 6. 그 외

- 화면 문구가 쉽고 친절해서 git을 잘 모르는 외주 아티스트한테 "이 주소 넣어서 받아" 하고 넘기기 좋겠다는 생각이 들었어요. 다만 그 사람들은 웹에서 이미지 미리보기를 원할 겁니다.
- 폰이 서버라는 것 자체가 불안 요소이기도 해요. 폰을 잃어버리거나 떨어뜨리면 거기 있던 보존 기록도 같이 사라지니까, 11 "전체 백업(zip)"을 외장 SSD나 PC로 주기적으로 자동으로 빼 주는 기능이 있으면 진짜 "마지막 보루"가 될 것 같습니다.
- 가격: GitHub LFS 데이터 팩 비용(월 5~10달러)을 아낄 수 있다면, 앱 일회성 결제로 1~2만 원은 바로 낼 의향이 있습니다. 단, LFS가 확실히 될 때만요.
