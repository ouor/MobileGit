## 여러 명이 함께 짚은 것 (기존 기능의 보이기·안전 문제)
1. **실패와 원본 사고가 안 보인다** (01, 03, 04, 05): 메인 목록에 "업데이트 1분 전"만 있음. 실패·N일 미동기화·토큰 문제·force-push·원본 삭제를 목록 배지와 상단 요약("정상 N / 주의 N")으로 보여 달라. "보존된 기록 0개"는 차별점으로 인정받았지만 기록이 생겼을 때 어떻게 보이는지 화면이 없음.
2. **ngrok은 기본 꺼짐, 깊숙이** (01, 02, 03, 04): 4명이 필요 없다고 함. 04는 "비밀번호 끄기 + ngrok 켜기" 조합을 동작으로 막으라고 요구.
3. **LFS 지원 여부가 화면 어디에도 없다** (03, 05): 지원하지 않는다면 그 사실을 미러 추가·PC 올리기·레포 상세에 명시해야 함. 03은 LFS 미러를 1년간 모르고 놓친 경험.
4. **동기화 주기가 안 보인다** (03): 설정에서 확인·변경 위치가 불분명.
5. **비밀번호 하나뿐, 폰 분실 대책 없음** (02, 03, 04): 기기별 토큰, 앱 잠금, 저장소 암호화 요구.
6. **QR 큰 화면은 덜 중요** (01, 03, 04, 05), **"PC 프로젝트 올리기"와 "빈 레포 만들기"가 겹친다** (04).

## 개별 요구 (대부분 새 기능)
- 01: 보존 기록 보기 화면, 의존성 파일(package.json 등)에서 레포 일괄 등록
- 02: 미러의 `field/*` 브랜치만 push 허용 후 원본으로 전달, USB 테더링·핫스팟 연결 안내, 사설 CA·SSH 주소·서브모듈 미러, 웹 diff, bundle 가져오기
- 03: Org 계속 따라가기(새 레포 자동 포함), 감사 증적 PDF/CSV, 정기 `git fsck`, Tailscale만 허용 모드, 정기 암호화 백업 내보내기, 상시 거치 모드, 복구 마법사
- 04: 업데이트 검토 후 반영 모드, 프로젝트 키트 번들(해시 목록 포함), 프로젝트 단위 안전 삭제, HTTPS(자체 서명), 메인 IP 숨김, 서버 자동 종료, 레포 태그·코드 검색, "외부로 무엇을 보내는지" 문서
- 05: LFS 서버, 큰 push 진행률, 로컬 레포 force-push 보존과 태그 보호

## 확정 결정과 부딪히는 것
- 02의 "미러에 push": 기획의 "미러는 읽기 전용"과 충돌. 04는 반대로 읽기 전용 구분을 장점으로 꼽음.
- LFS·SSH: 1차에서 제외 범위로 확정됨.
- 2차 사이클은 1차 문제와 UI 개선만 반영한다(사용자 지시). 새 기능은 범위 밖.

## 팀장 권장안 (PM 판단 대상)
- **2차 반영 권장**: 위 1~4번과 6번(기존 기능의 표시·기본값·안전장치), 1차 QA 관찰(PC 올리기 안내에서 뒤로 가기), 4번은 설정에 주기 표시만.
- **2차 범위 밖으로 기록 권장**: LFS 서버, 미러 push, HTTPS, 기기별 토큰, 앱 잠금·암호화, 검토 모드, 감사 리포트, Org 계속 따라가기 등 새 기능. PRD에 "향후 검토"로 남기고 이유를 적음.
- 5번 중 화면 문구로 바로 해결되는 부분(토큰이 키스토어에 저장된다는 설명, 내보내기 파일 위치·암호화 여부 표시)은 2차에 포함 권장.
