## 1. 개인 프로젝트 코드 백업과 여러 기기에서 다루는 실제 흐름

솔직히 "체계"라고 부를 만큼 깔끔하지는 않고, 몇 번 데이고 나서 덧대다 보니 지금 모양이 됐습니다. 순서대로 말하면 이렇습니다.

1. **새 프로젝트 시작**: 집 데스크톱에서 Android Studio로 만들고 바로 `git init` 합니다. GitHub에 private 레포를 만들어 `origin`으로 붙입니다.
2. **두 번째 원격 추가**: 예전에 GitHub 계정 2FA 복구 코드를 잃어버려서 하루 반나절 계정에 못 들어간 적이 있어요. 그 뒤로는 GitLab에도 같은 이름의 private 레포를 만들고, `origin`에 push URL을 두 개 걸어 둡니다 (`git remote set-url --add --push origin ...`). 한 번 push하면 둘 다 갑니다. 다만 새 레포 만들 때마다 이 설정을 손으로 해야 해서 가끔 빼먹습니다. 실제로 지금 레포 중 두 개는 GitLab 쪽이 몇 달 전 커밋에 멈춰 있는 걸 얼마 전에 발견했어요.
3. **로컬 오프라인 백업**: 집에 시놀로지 NAS가 있어서 한 달에 한 번쯤 `git clone --mirror`로 받은 bare 레포들을 NAS에 rsync하는 셸 스크립트를 돌립니다. cron으로 걸어 두고 싶었는데 데스크톱이 항상 켜져 있지 않아서 결국 생각날 때 수동으로 돌립니다. 그래서 "한 달에 한 번"이 실제로는 두세 달에 한 번이에요.
4. **회사 맥북에서 작업**: 점심시간이나 퇴근 후 회사 근처 카페에서 사이드 프로젝트를 만질 때가 있습니다. 회사 노트북에 개인 GitHub 계정 SSH 키를 올리는 게 찜찜해서, 개인용 키를 따로 만들어 `~/.ssh/config`에 호스트 별칭으로 나눠 씁니다. 그래도 회사 보안 정책상 개인 레포 clone이 꺼림칙해서 요즘은 거의 안 하고, 대신 아이디어를 메모만 해 둡니다.
5. **폰(Termux)에서**: 출퇴근 지하철에서 봇 코드 오타 하나 고치거나, 블로그 마크다운 글 수정할 때 씁니다. Termux에 git, openssh, neovim 깔아 두고 GitHub에서 clone해서 작업 후 push합니다. 지하철 안에서 데이터가 끊기면 push가 실패하고, 내릴 때 까먹어서 집 데스크톱에서 다른 걸 수정하다가 충돌 나는 일이 몇 번 있었어요.
6. **릴리스 / 빌드 산출물**: 서명 키스토어(.jks)와 `local.properties`, API 키가 들어간 파일은 git에 안 넣고, 1Password에 첨부파일로 따로 보관합니다. 이게 코드 백업과 분리돼 있어서 "레포만 있으면 복구 끝"이 아닌 게 늘 신경 쓰입니다.
7. **남의 레포 보관**: 참고하려고 스타 눌러 둔 오픈소스 레포가 삭제되거나 private로 바뀐 경험이 두 번 있어서 (하나는 DMCA, 하나는 작성자가 그냥 지움), 중요한 건 GitHub에서 fork 해 두고 NAS에도 mirror로 받아 둡니다. 근데 fork는 원본이 사라지면 같이 애매해지기도 하고, 업데이트 따라가려면 직접 sync 눌러야 합니다.

정리하면 **GitHub(주) + GitLab(보조) + NAS(오프라인, 불규칙) + 1Password(비밀 파일)** 네 군데에 흩어져 있고, 이걸 맞추는 건 전부 제 기억력에 의존하고 있습니다.

## 2. 단계별 불편한 점과 있었으면 하는 기능

| 단계 | 불편했던 점 | 있었으면 하는 것 |
|---|---|---|
| 새 레포 만들 때 두 번째 원격 설정 | 매번 손으로 해야 하고 빼먹음. 빼먹어도 아무도 안 알려 줌 | "이 GitHub 계정의 레포는 전부 자동으로 미러" 같은 규칙 기반 등록 |
| 미러 최신성 확인 | GitLab 쪽이 몇 달 멈춘 걸 우연히 발견 | 미러별 "마지막 동기화 시각 / 원본보다 몇 커밋 뒤처짐" 한눈에 보기, 실패하면 알림 |
| NAS 백업 | 데스크톱이 꺼져 있으면 안 돌아감. 결국 수동 | 항상 켜져 있는 기기에서 주기적으로 fetch. 폰은 사실상 항상 켜져 있음 |
| 회사 노트북 | 개인 계정 자격증명을 회사 기기에 두기 싫음 | 레포 단위 읽기 전용 토큰, 기기별로 발급하고 언제든 폐기 |
| Termux 작업 | 네트워크 끊기면 push 실패, 까먹음 | 일단 폰 로컬에 push하고 나중에 원본으로 올려 주는 흐름 (폰이 중간 버퍼) |
| 남의 레포 보관 | 삭제/비공개 전환 시 날아감. fork는 sync 수동 | URL만 넣으면 주기적으로 따라가되, **원본이 force-push 하거나 사라져도 내 쪽 기록은 안 지워지는** 아카이브 모드 |
| 전체 | 4군데에 흩어진 상태를 아무도 요약해 주지 않음 | 대시보드 하나 |

특히 강조하고 싶은 건 **force-push 대응**입니다. 미러를 그냥 `fetch --prune`으로 따라가면 원본이 히스토리를 날렸을 때 제 쪽도 같이 날아갑니다. 아카이브가 목적이면 덮어쓰기 전 상태를 ref로 남겨 두거나 스냅샷을 떠 둬야 의미가 있어요.

## 3. 이런 앱이 있다면 언제 쓰고, 언제 안 쓸지

### 쓰겠다 싶은 상황
- **서랍 속 Pixel 6a 재활용**: 이게 제일 끌립니다. 충전기 꽂아서 집 와이파이에 두고 "개인 git 백업 서버"로 쓰면 NAS 스크립트를 대체할 수 있을 것 같아요. 전기도 거의 안 먹고요.
- **오픈소스 아카이브**: 참고용 레포 수십 개를 URL만 붙여넣어 따라가게 해 두는 용도. 이건 바로 쓸 것 같습니다.
- **지하철 Termux 작업의 중간 저장소**: 폰 안에서 Termux → 이 앱으로 로컬 push (localhost라 네트워크 무관), 나중에 집에서 데스크톱이 폰에서 pull. 이건 생각만 해도 편합니다.
- **해외여행/출장 중**: 노트북만 들고 갔을 때 Tailscale로 집에 있는 폰에 접속해서 clone. 다만 이건 GitHub 접속이 되는 상황이면 굳이 안 쓸 것 같긴 해요.

### 안 쓸 이유 / 걱정되는 점
- **배터리와 안드로이드 백그라운드 제한**: 안드로이드 개발자로서 제일 먼저 의심하는 부분입니다. Doze, 앱 대기 버킷, 제조사별 배터리 최적화(특히 삼성) 때문에 백그라운드 서버가 몇 시간 뒤에 조용히 죽는 걸 너무 많이 봤어요. Foreground Service로 상시 알림 띄우는 건 이해하는데, Android 14부터 FGS 타입 선언이 까다로워져서 어떤 타입으로 버틸지 궁금합니다. "서버가 살아 있다"를 신뢰할 수 없으면 백업 용도로는 못 씁니다.
- **ngrok으로 외부 공개**: 제 코드를 인터넷에 열린 주소로 노출하는 건 기본적으로 싫습니다. 무료 ngrok 주소는 스캐너들이 금방 찾아오고, 인증이 약하면 바로 털립니다. 저는 Tailscale만 켜고 ngrok은 끌 것 같아요. 기본값은 반드시 꺼져 있어야 합니다.
- **폰 자체의 신뢰성**: 폰은 잃어버리고, 떨어뜨리고, 초기화합니다. 폰을 "유일한" 백업으로 쓰면 오히려 위험해요. 저한텐 3번째, 4번째 사본 정도의 위치입니다.
- **저장 공간**: 안드로이드 레포 몇 개만 해도 히스토리에 바이너리 들어가 있으면 수 GB입니다. 폰 내부 저장소에 두면 사진이랑 싸우게 돼요.
- **자격증명 저장**: private 레포 미러하려면 GitHub 토큰을 앱에 줘야 하는데, 그 토큰이 어떻게 저장되는지 (Android Keystore로 암호화하는지, 백업에 포함되는지) 명확하지 않으면 안 줍니다.
- **오픈소스가 아니면**: 내 코드 전체와 토큰을 맡기는 앱인데 소스를 못 보면 신뢰하기 어렵습니다. 최소한 네트워크로 뭘 보내는지는 확인할 수 있어야 해요.

## 4. 비교/참고 제품

| 제품 | 좋은 점 | 아쉬운 점 |
|---|---|---|
| **Gitea / Forgejo** (NAS나 라즈베리파이에 설치) | 미러 기능이 이미 있음 (pull mirror, 주기 설정). 웹 UI 훌륭. Forgejo는 커뮤니티 운영이라 신뢰 | 서버를 따로 굴려야 함. 시놀로지에 Docker로 올렸다가 업데이트 관리 귀찮아서 접음. 폰에서 돌리는 건 사실상 불가 |
| **Termux + git + sshd** | 지금도 씀. 폰을 ssh git 원격으로 쓰는 건 이미 가능 (`ssh -p 8022 폰IP`로 bare 레포 push) | 전부 수동. 미러 자동 동기화 없음, sshd가 Termux 꺼지면 죽음, 웹 브라우징 없음, 일반 사용자에겐 진입장벽 높음 |
| **GitHub fork / GitLab pull mirroring** | 클릭 몇 번이면 끝. GitLab push mirror는 꽤 안정적 | 결국 같은 클라우드 회사 안. 계정 잠기면 같이 못 씀. GitLab 무료 플랜 미러 기능 제약 변화가 잦음 |
| **Software Heritage** | 공개 오픈소스 영구 보존. 원본이 사라져도 남음 | 공개 레포만, 내가 원할 때 바로 받기 불편. 개인 백업 용도는 아님 |
| **Syncthing** | 폰↔PC 파일 동기화로는 최고. 서버 없이 P2P | `.git` 폴더를 Syncthing으로 동기화하다가 인덱스 깨져서 한 번 크게 데임. git과는 궁합 나쁨 |
| **MGit (안드로이드 git 클라이언트)** | 폰에서 clone/commit 가능한 GUI | 클라이언트지 서버가 아님. 업데이트도 거의 멈춤 |
| **Tailscale** | 설정 몇 분이면 끝, 포트 안 열어도 됨. 이 앱의 원격 접속 수단으로는 최선이라고 봄 | 안드로이드 VPN 슬롯을 하나 차지해서 다른 VPN과 동시 사용 불가 |

## 5. 꼭 있어야 하는 것 3가지 / 없어도 되는 것

### 꼭 있어야 하는 것
1. **믿을 수 있는 자동 미러링 + 상태 가시성**: 주기적으로 fetch하고, 실패하면 알려 주고, 레포마다 "마지막 성공 시각"이 보여야 합니다. 그리고 원본이 force-push하거나 레포가 사라져도 **내 쪽 히스토리는 보존**되는 옵션. 이게 이 앱의 존재 이유라고 생각합니다.
2. **기본이 닫혀 있는 보안**: 외부 노출(ngrok)은 기본 꺼짐, 접속은 반드시 인증 (기기/레포별 토큰, 폐기 가능), 토큰은 Android Keystore로 암호화 저장, 접속 로그 보기. 같은 와이파이라도 인증 없이 열리면 안 됩니다 (카페 와이파이 생각하면 끔찍).
3. **표준 git 프로토콜로 PC에서 그냥 쓸 수 있을 것**: `git clone http://폰IP:포트/repo.git` 또는 ssh로 평소 쓰던 그대로 clone/pull/push. 전용 클라이언트를 깔아야 하면 안 씁니다. 그리고 폰 안의 Termux에서도 localhost로 붙을 수 있으면 좋겠어요.

### 없어도 되는 것
- **웹 UI에서 코드 편집, 이슈, PR, 위키**: GitHub 흉내는 필요 없습니다. 브라우징은 파일 트리, 커밋 로그, README 렌더링, 파일 보기 정도면 충분합니다.
- **ngrok 통합**: 넣더라도 후순위. Tailscale이 있으면 저는 안 씁니다. 오히려 공격 표면만 늘어요.
- **CI/빌드 실행**: 폰에서 Gradle 돌릴 생각 전혀 없습니다.
- **소셜 기능, 공유 링크, 팀 기능**: 개인용이면 충분.
- **화려한 홈 화면 위젯**: 상태 알림 하나면 됩니다.

## 6. 그 외에 하고 싶은 말

- **"폰이 유일한 저장소"가 아니라 "추가 사본"이라는 포지셔닝**이 맞다고 봅니다. 폰 분실 시를 대비해 이 앱의 레포들을 다시 다른 곳(외장 SD, NAS, 다른 폰)으로 내보내는 export 기능이 있으면 3-2-1 백업 그림이 완성돼요.
- **저장 위치 선택**: 내부 저장소 / 앱 전용 폴더 / SD 카드를 고를 수 있으면 좋겠습니다. 단, 앱 삭제 시 데이터가 같이 날아가는지 아닌지를 설치 단계에서 분명히 알려 주세요. 안드로이드 개발자인 저도 scoped storage 때문에 헷갈리는데 일반 사용자는 더할 겁니다.
- **LFS**: 제 게임 사이드 프로젝트 하나가 Git LFS를 써요. 지원 안 하면 그 레포만 반쪽 백업이 되니, 최소한 "이 레포는 LFS 객체가 빠져 있음" 경고라도 주세요.
- **서랍 폰 모드**: 남는 폰을 전용 서버로 쓰는 사람이 꽤 있을 거라 봅니다. 충전 상태 유지 권장(배터리 80% 제한 안내), 화면 꺼진 상태 운영, 재부팅 후 자동 시작 같은 "전용 기기 모드"가 있으면 바로 Pixel 6a에 깔겠습니다.
- 배터리/백그라운드 문제를 어떻게 해결했는지 앱 안에서 솔직하게 보여 주세요. "삼성 기기는 배터리 최적화 예외 등록 필요" 같은 안내를 기기별로 해 주면 신뢰가 훨씬 올라갑니다.
- 오픈소스로 공개되면 기여할 의향도 있습니다. 특히 JGit 기반인지, 네이티브 git 바이너리를 넣는지 궁금하네요. JGit이면 큰 레포에서 메모리 문제가 걱정됩니다.
