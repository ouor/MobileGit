# 인터뷰 04 — 9년 차 코딩 강사 (부트캠프 + 대학 실습)

- 대상: 부트캠프(웹 풀스택, 6개월 과정)와 대학 실습 과목(자료구조/웹프로그래밍 실습)을 맡는 강사, 9년 차
- 환경: 수강생 25~35명, 강의실 와이파이 품질 들쭉날쭉, 일부 대학 실습실은 외부 인터넷이 방화벽으로 막혀 있음
- 주 사용 도구: GitHub (개인 계정 + GitHub Classroom), VS Code, USB 메모리, 학교 LMS, Discord/카카오톡 오픈채팅, 노트북 핫스팟, 가끔 Gitea(개인 NAS)

## 1. 수업에서 레포를 나눠 주고 모으는 실제 작업 흐름

### 수업 준비 (전날 ~ 당일 아침)
1. GitHub 개인 계정에 있는 예제 레포(`week05-express-todo` 같은 이름)를 정리합니다. 브랜치를 `step-01`, `step-02`... 식으로 단계별로 나눠 두거나, 태그로 `start`/`solution`을 찍어 둡니다.
2. 부트캠프 쪽은 GitHub Classroom으로 과제 링크를 만들어 두고, 대학 쪽은 학생들이 GitHub 계정을 안 만든 경우도 많아서 LMS에 zip 파일을 같이 올립니다.
3. 실습실이 외부 인터넷 막힌 곳이면 전날 밤에 레포를 `git bundle`로 만들거나 그냥 zip으로 떠서 USB 메모리 3~4개에 복사해 둡니다. `node_modules`까지 넣은 버전을 따로 만들 때도 있습니다(npm install이 안 되니까).

### 수업 시작 (배포)
4. 와이파이가 되는 날: 채팅방에 GitHub 주소 올리고 "clone 하세요". 30명이 동시에 clone 하면 첫 5분은 꼭 몇 명이 멈춥니다. 대학 공용 와이파이는 GitHub이 유난히 느릴 때가 있어요.
5. 와이파이가 안 되거나 막힌 날: USB를 돌립니다. 30명이 USB 4개 돌려 받는 데 10~15분 날아갑니다. zip으로 받은 학생은 `.git`이 없어서 나중에 제가 고친 걸 pull 할 방법이 없습니다.
6. 가끔은 제 노트북에서 `python -m http.server`로 zip을 띄우고 같은 와이파이에서 받게 하는데, 강의실 와이파이가 AP 격리(클라이언트끼리 통신 차단)인 경우가 있어서 그날은 실패합니다. 그럴 땐 제 폰 핫스팟에 학생 일부를 붙이는데 핫스팟은 10명 남짓이 한계예요.

### 수업 중 (수정 반영)
7. 수업하다 보면 예제에 오타나 버그가 꼭 나옵니다. 아니면 질문 받고 즉석에서 예제를 하나 추가하기도 하고요. 제 노트북에서 고쳐서 GitHub에 push → 학생들에게 "pull 하세요".
8. 인터넷이 막힌 실습실에서는 이게 불가능해서, 화면에 수정한 코드를 띄우고 "직접 따라 고치세요"라고 합니다. 여기서 오타 내는 학생이 꼭 생기고 다음 단계가 어긋납니다.

### 과제 수집
9. 부트캠프: GitHub Classroom으로 학생 레포가 자동 생성되니까 마감 후 Classroom 대시보드에서 확인. 다만 학생들이 push를 안 하거나 엉뚱한 레포에 push 하는 일이 잦습니다.
10. 대학: 상당수가 GitHub 계정이 없거나 2FA 때문에 push가 막혀서, 결국 LMS에 zip 업로드로 받습니다. zip으로 받으면 커밋 이력이 없어서 "언제 무엇을 했는지" 안 보입니다. 표절 의심 건 확인할 때 아쉽습니다.
11. 수업 중 실습 결과를 바로 보고 싶을 때는 학생 자리로 걸어가서 화면을 봅니다. 30명이면 다 못 봅니다.

### 수업 후
12. 모은 레포/zip을 제 PC 폴더에 `학번_이름` 식으로 풀어 놓고 하나씩 열어서 실행해 봅니다. 채점용 스크립트를 돌리기도 하고요.
13. 학기 끝나면 외장 SSD에 학기별로 백업합니다. 예제 레포는 해마다 조금씩 바뀌는데 "작년 버전"을 찾는 일이 생각보다 많아서 태그를 찍어 두려고 노력은 하는데 자주 까먹습니다.

## 2. 단계별 불편한 점과 원하는 기능

| 단계 | 불편한 점 | 있었으면 하는 것 |
|---|---|---|
| 준비 | 인터넷 막힌 실습실용으로 USB/zip/bundle을 따로 만들어야 함. 전날 밤에 고친 걸 USB에 반영 안 해서 낡은 버전을 나눠 준 적 있음 | GitHub 원본을 미러로 들고 다니다가 출발 전에 "동기화" 한 번이면 최신 상태 보장 |
| 배포 | 30명 동시 clone 시 느림, USB 돌리기에 10~15분, zip 받은 학생은 `.git` 없음 | 강의실 로컬에서 바로 `git clone http://192.168.x.x/...` — 진짜 git 레포로 받게 |
| 수업 중 수정 | 인터넷 막히면 수정 반영 불가, 학생이 손으로 따라 고치다 어긋남 | 제 노트북에서 폰으로 push → 학생들 `git pull` 끝. 나중에 인터넷 되면 폰이 GitHub 원본으로 다시 push(또는 제가 PC에서 GitHub로 push) |
| 수집 | 계정 없는/2FA 막힌 학생은 push 못 함, zip 제출은 이력 없음 | 학생별로 push 가능한 레포를 즉석 생성. 계정 대신 수업용 간단 토큰이나 레포별 비밀번호 |
| 확인 | 30명 화면 다 못 봄 | 브라우저로 학생 레포 목록, 최근 커밋 시각, diff를 폰/노트북에서 훑어보기 |
| 보관 | 학기별 백업 수작업, 태그 깜빡함 | 레포 스냅샷/태그 자동 기록, 나중에 zip으로 한꺼번에 내보내기 |

특히 강조하고 싶은 건 두 가지예요.
- **AP 격리 문제**: 강의실 와이파이가 클라이언트 간 통신을 막는 경우가 실제로 꽤 있습니다. 그럼 "같은 와이파이에서 사설 IP" 시나리오가 안 됩니다. 이때 폰이 자체 핫스팟을 켜고 거기서 서버를 돌리면 되는데, 핫스팟 동시 접속 한도(기종마다 10~15명 정도)가 걸려요. 이 상황을 앱이 알려 주면 좋겠습니다("다른 기기에서 접속 안 됨: AP 격리 의심" 같은 진단).
- **수업 중 수정 흐름**: 제가 원본(GitHub)과 폰 미러 양쪽을 동시에 신경 쓰고 싶지 않아요. "폰 미러에 push한 걸 나중에 원본으로 돌려보내기" 혹은 "원본이 바뀌면 미러 갱신"이 충돌 없이 단순했으면 합니다. 충돌 나면 수업 중에 해결할 시간이 없습니다.

## 3. 어떤 상황에서 쓰겠나 / 쓰지 않을 이유

### 쓰겠다
- **인터넷 막힌 대학 실습실**: 이게 제일 큽니다. USB 돌리기를 없앨 수 있으면 매 수업 10분 이상 법니다.
- **와이파이가 느린 부트캠프 강의실**: GitHub 대신 폰에서 받게 해서 첫 clone 시간을 줄이기.
- **수업 중 즉석 수정 배포**: 인터넷 상황과 무관하게 "pull 하세요" 한마디로 끝내기.
- **특강/외부 출강**: 처음 가는 기관은 네트워크 사정을 모릅니다. 폰 하나 들고 가서 핫스팟+서버로 해결되면 마음이 편할 것 같아요.
- **학기별 아카이브**: 예제 레포의 연도별 상태를 폰(혹은 폰에서 내보낸 백업)에 들고 있기.

### 안 쓸 이유
- **30명 동시 접속을 폰이 버티느냐**: 제일 걱정입니다. 30명이 동시에 clone 하면 폰이 뜨거워지거나 앱이 백그라운드에서 죽을까 봐요. 수업 중에 서버가 죽으면 그 수업은 망합니다. 동시 접속 테스트 결과를 보여 주지 않으면 믿고 못 씁니다.
- **안드로이드 배터리 최적화**: 화면 끄면 서버가 죽는다든지, 삼성 폰 절전 모드가 앱을 재운다든지. 이건 겪어 봐서 압니다.
- **ngrok/Tailscale은 수업용으로는 거의 안 씀**: 학생 30명에게 Tailscale 설치시키는 건 현실성 없습니다. ngrok은 무료 플랜 제한, 그리고 학교 방화벽이 ngrok 도메인을 막는 경우도 있어요. 제게는 "같은 네트워크 사설 IP"와 "폰 핫스팟"이 전부입니다. 집에서 제 노트북으로 접속할 때나 Tailscale을 쓰겠죠.
- **학생 데이터/보안**: 학생 과제를 개인 폰에 담는 게 학교 규정상 애매할 수 있습니다. 폰 분실 시 위험도 있고요. 앱 잠금이나 저장소 암호화 정도는 있어야 마음이 놓입니다.
- **GitHub Classroom 이미 쓰는 경우**: 인터넷 잘 되는 부트캠프 강의실이면 굳이 바꿀 이유가 없습니다. 이 앱은 "네트워크 나쁜 곳"용 보조 도구 위치일 것 같습니다.

## 4. 비교/참고할 만한 제품

| 제품 | 좋은 점 | 아쉬운 점 |
|---|---|---|
| **GitHub Classroom** | 학생별 레포 자동 생성, 템플릿 배포, 마감 관리. 부트캠프에서 주력 | 인터넷 필수, 학생 GitHub 계정 필수. 대학 신입생들 계정 만들고 2FA 설정하는 데만 한 시간 날아감 |
| **Gitea / Forgejo** (개인 NAS에 설치) | 가볍고 GitHub과 UI 비슷, 미러 기능 있음(원본 주기적 pull) | NAS를 강의실에 들고 갈 수 없음. 노트북에 Docker로 띄우면 되지만 강의 직전 세팅이 부담. 미러 레포는 읽기 전용이라 수업 중 수정 흐름에 안 맞음 |
| **GitLab (셀프호스팅)** | 기능 풍부 | 무겁습니다. 노트북에서 돌리기 부담, 강의용으론 과함 |
| **`git daemon` / `git http-backend` 수동 실행** | 노트북에서 몇 줄이면 됨, 진짜 git 프로토콜 | 매번 명령어 기억해야 하고 push 권한 설정 귀찮음, 웹 UI 없음. Windows 노트북에서는 더 번거로움 |
| **`git bundle` + USB** | 인터넷 0이어도 됨, `.git` 유지 | 학생들이 bundle에서 clone 하는 법을 몰라서 설명 시간이 듬. 업데이트 배포 불가 |
| **LMS zip 업/다운로드** | 학교 공식 경로, 계정 문제 없음 | git 이력 없음, 제출물 정리 수작업 |
| **LocalSend / Snapdrop** | 같은 와이파이에서 파일 뿌리기 편함 | 파일 전송일 뿐 git이 아님. AP 격리면 똑같이 막힘 |
| **Termux + git + 간단 서버** | 실제로 한 번 해 봤음. 폰에서 `git daemon` 돌리는 것까지는 됨 | 세팅을 남한테 설명할 수 없는 수준. 화면 끄니 죽었음. 이 경험 때문에 이 앱 아이디어에 관심이 갑니다 |
| **Replit / Codespaces 등 클라우드 IDE** | 설치 없이 바로 실습 | 인터넷 필수, 무료 한도, 학교 방화벽 |

## 5. 꼭 있어야 하는 것 3가지 / 없어도 되는 것

### 꼭 있어야 하는 것
1. **같은 네트워크(와이파이·폰 핫스팟)에서 안정적인 clone/pull, 30명 동시 접속 버티기**  
   접속 주소를 QR코드로 크게 띄워 주는 화면이 같이 있으면 완벽합니다(빔프로젝터에 폰 화면을 띄우거나 칠판에 적기). 화면 꺼져도 서버 유지(포그라운드 서비스 + 알림).
2. **GitHub 원본 미러 + 원터치 동기화, 그리고 수업 중 수정을 폰에 push 할 수 있는 것**  
   원본 → 폰 갱신은 버튼 하나, 폰에서 바뀐 걸 원본에 돌려보낼 때 충돌이 나면 수업 끝나고 처리할 수 있게 "보류" 상태로 표시만 해 줘도 됩니다.
3. **학생 과제 수집용 push 받기 (계정 없이 간단한 인증)**  
   레포별 비밀번호 하나, 또는 학생이 `학번` 이름으로 레포를 push 하면 자동 생성. 그리고 브라우저에서 "누가 언제 마지막으로 push 했나" 목록 한 장.

### 없어도 되는 것
- 이슈, PR, 코드 리뷰 코멘트 같은 협업 기능: GitHub에서 하면 됩니다.
- 브라우저 UI 안의 코드 편집기: 보기만 되면 충분합니다.
- ngrok 연동: 수업에선 안 씁니다(개인 용도로는 몰라도 우선순위 낮음).
- CI/Actions 류: 필요 없습니다.
- 화려한 코드 하이라이팅/통계 그래프: 있으면 좋지만 우선순위 낮음.

## 6. 그 외에 하고 싶은 말

- **"수업 모드" 같은 묶음이 있으면 좋겠어요.** 버튼 하나로: 서버 시작, 화면 꺼짐 방지/포그라운드 유지, 접속 QR 표시, 학생 push 허용 on, 끝나면 off. 수업 직전 30초 안에 준비가 끝나야 실제로 씁니다. 강의 시작 5분 전에 설정 화면 뒤지는 건 못 합니다.
- **실패했을 때 빨리 알 수 있게.** "학생 PC에서 접속이 안 돼요"가 나왔을 때 앱이 원인을 짚어 주면(다른 네트워크, AP 격리, 방화벽 등) 큰 도움입니다. 수업 중엔 디버깅할 여유가 없어요.
- **학생 쪽은 아무것도 설치하지 않아야 합니다.** git만 있으면 되는 구조여야 하고, 주소는 짧아야 합니다. `http://192.168.0.12:8080/week05.git` 정도가 한계예요. 포트 번호도 학생들이 자주 틀립니다.
- **HTTP 인증 프롬프트 주의.** 학생 PC에 Windows 자격 증명 관리자가 이상한 값을 캐시하면 다음 수업에 꼬입니다. 읽기는 인증 없이, 쓰기만 인증하는 옵션이 있었으면 합니다.
- 실제로 써 보라고 하면 써 볼 의향 있습니다. 다만 첫 수업에 바로 투입하진 않고, 제 노트북 두세 대와 조교 노트북으로 동시 clone 테스트부터 해 보겠습니다. 폰은 갤럭시 S23을 쓰고 있고, 수업용 공기계(갤럭시 A 시리즈)를 하나 따로 둘 생각도 있습니다.
