# 인터뷰 03 — 디지털 노마드 프리랜서 풀스택 개발자

- 경력: 7년 차 프리랜서 풀스택 (Node/TypeScript, Python, 가끔 Flutter)
- 작업 환경: 맥북 프로 14" 한 대, 안드로이드 폰(갤럭시 S 시리즈) 테더링, 카페, 기차, 해외 에어비앤비와 코워킹
- 고객사 호스팅: A사 GitHub(조직 계정), B사 사내 GitLab(셀프 호스팅, VPN 필요), C사 Bitbucket + Jira, 개인 프로젝트는 GitHub

## 1. 이동하며 일할 때 코드와 레포를 실제로 어떻게 관리하나요?

솔직히 체계라기보다는 몇 년 동안 사고를 겪으면서 쌓인 습관에 가깝습니다. 하루 흐름으로 보면 이렇습니다.

1. **출발 전(숙소 와이파이가 좋을 때)**
   - 그날 만질 고객사 레포를 모두 `git fetch --all`로 당겨 둡니다. 기차나 비행기에서 원격에 못 붙는 일이 많아서 "오프라인에서 필요한 건 미리 받아 둔다"가 1순위입니다.
   - 의존성도 미리 받습니다(`pnpm install`, `pip download`). git보다 npm이 더 큰 문제일 때도 많습니다.

2. **이동 중 작업(기차, 카페, 테더링)**
   - 로컬 브랜치에서 작업하고 커밋은 자주 하는데, push는 못 하거나 일부러 안 합니다. 테더링으로 수백 MB짜리 push를 하면 데이터가 날아가고, 중간에 끊기면 다시 해야 하니까요.
   - 그래서 하루 이틀은 "로컬에만 있는 커밋"이 쌓입니다. 이 시간이 제일 불안합니다. 노트북을 잃어버리거나 SSD가 죽으면 그대로 날아갑니다.

3. **백업**
   - 노트북 전체는 Time Machine을 외장 SSD에 받는데, 솔직히 들고 다니다 보니 2~3주에 한 번 꽂습니다.
   - 코드 자체의 진짜 백업은 "원격에 push"입니다. 고객사 레포에 WIP 브랜치를 올리는 건 고객 쪽 CI가 돌거나 리뷰어가 알림을 받아서 눈치가 보입니다. 그래서 개인 GitHub에 private 미러를 만들어 `backup` 리모트로 push하기도 하는데, 계약서상 고객 코드를 개인 계정에 올리는 게 애매해서 찜찜합니다.
   - 일부 레포는 `git bundle create`로 묶어서 iCloud/Google Drive에 넣어 둔 적도 있습니다. 복원은 한 번도 깔끔하게 해 본 적이 없습니다.

4. **동기화와 다른 기기로 옮기기**
   - 기기가 사실상 노트북 하나라 "다른 기기로 옮기기"는 주로 노트북이 고장 났을 때, 혹은 숙소에 맡겨 둔 보조 미니PC나 고객사에서 빌려준 노트북으로 옮길 때입니다.
   - 2023년에 발리에서 맥북 로직보드가 나갔을 때, 현지에서 급히 산 윈도 노트북으로 옮겼습니다. 원격에 올라간 건 clone으로 받았지만, push 안 한 3일치 커밋은 Time Machine 백업이 일주일 전 거라 날아갔습니다. 그때부터 "push 못 할 때 어딘가에 두는 곳"이 필요하다고 생각했습니다.
   - B사 GitLab은 VPN 없으면 접근이 안 되는데, 해외 숙소에서 VPN 클라이언트가 막히는 경우가 있어서 그 레포만은 로컬 사본이 사실상 유일한 사본이 되는 날이 있습니다.

## 2. 각 단계에서 불편했던 점과, 있었으면 하는 기능

| 단계 | 불편했던 점 | 있었으면 하는 것 |
|---|---|---|
| 출발 전 fetch | 레포가 3개 서비스에 10개 넘게 흩어져 있어서 하나씩 fetch. 하나 빼먹으면 기차에서 막힘 | 등록한 레포를 한 번에, 혹은 와이파이 잡힐 때 자동으로 최신화 |
| 이동 중 커밋 | 로컬에만 있는 커밋이 불안. 테더링으로 원격 push는 비싸고 느림 | 노트북 바로 옆에 있는 폰에 USB나 핫스팟 내부망으로 push하면 "일단 안전" 상태가 되는 것. 외부 데이터 안 쓰고 |
| 백업 | 고객 코드를 개인 클라우드나 개인 GitHub에 올리는 게 계약상 애매 | 내 소유 기기 안에만 있는 사본. 제3자 서버를 안 거치는 게 오히려 장점 |
| 원본으로 되돌리기 | 폰에 쌓인 커밋을 나중에 원래 GitHub/GitLab으로 올리는 과정이 수동 | 와이파이 잡히면 폰이 원본 쪽으로 대신 push해 주는 옵션 (계정 권한 문제는 신중히) |
| 기기 교체 | 새 노트북에서 레포 10개를 각각 다른 서비스에서 clone, 인증 다시 설정 | 폰 하나에서 전부 clone. 인증 하나로 끝 |
| VPN 필요한 레포 | VPN 안 되는 날은 접근 불가 | 미리 미러링해 두면 읽기는 언제든 가능 |

추가로 바라는 것:
- **끊김에 강한 전송**. 테더링은 5분마다 끊깁니다. clone/push가 중간에 끊겨도 다시 하면 이어지거나, 최소한 레포가 깨지지 않아야 합니다.
- **배터리와 발열 관리**. 폰이 서버 역할을 하면 테더링까지 같이 돌릴 때 엄청 뜨거워집니다. 기차에서 폰 배터리가 0이 되면 길 찾기, 결제, 테더링 다 끝입니다.
- **"이 레포는 원본보다 몇 커밋 앞/뒤" 상태 표시**. 폰 화면에서 한눈에.

## 3. 이런 앱이 있다면 어떤 상황에서 쓰겠나요? 쓰지 않을 이유는?

**쓸 상황**
- 기차, 비행기 전후로 "커밋은 했는데 원격에 못 올린" 상태를 폰으로 즉시 백업. 이게 제 입장에서 가장 큰 가치입니다. 노트북과 폰이 따로 도난당할 확률은 낮으니까요.
- 출국 전 고객사 레포 전부를 폰에 미러로 받아 두기. 현지에서 VPN이나 GitHub 접속이 불안정해도(실제로 중국 출장 때 GitHub가 매우 느렸습니다) 폰에서 clone 가능.
- 노트북 고장 시 비상 복구용. 새 기기에서 폰 하나로 전부 받기.
- 고객 미팅에서 노트북 없이 폰 브라우저로 "이 코드 여기 있어요" 보여주기. 가끔 있습니다.

**쓰지 않을 이유**
- **보안과 계약**. 고객 코드가 분실 가능성 높은 폰에 평문으로 있다는 것. 폰 잃어버리면 노트북 잃어버린 것만큼 위험해집니다. 앱 데이터 암호화와 원격 삭제가 없다면 일부 고객 레포는 못 넣습니다.
- **ngrok 노출**. ngrok 주소로 내 git 서버가 인터넷에 열린다는 게 꺼림칙합니다. 인증이 약하면 고객 코드가 공개 인터넷에 노출되는 셈이라, 그 모드는 아마 안 켭니다. Tailscale이면 괜찮습니다.
- **배터리와 안정성**. 안드로이드가 백그라운드 앱을 죽여서 정작 push할 때 서버가 꺼져 있으면 바로 안 씁니다. 한두 번만 실패해도 신뢰가 깨집니다.
- **용량**. 모노레포나 LFS 많은 레포는 폰 저장공간을 금방 먹습니다.
- 이미 GitHub이 잘 되는 환경이면 굳이 필요 없습니다. 이 앱은 "인터넷이 나쁠 때"의 보험입니다.

## 4. 비교하거나 참고할 만한 제품

| 제품 | 좋은 점 | 아쉬운 점 |
|---|---|---|
| **Termux + git + openssh** | 실제로 써 봤습니다. 폰에 bare 레포 만들고 ssh로 push. 공짜고 진짜 git | 설정이 손이 많이 가고, Termux가 백그라운드에서 자꾸 죽음(wake-lock 걸어야 함). 미러 자동 갱신은 cron 직접 구성. 비개발자 친화성 0 |
| **Gitea / Forgejo** (셀프 호스팅) | 미러 기능(pull mirror)이 정확히 원하는 것. 웹 UI 훌륭 | 서버나 홈랩이 필요. 노마드라 집에 상시 켜 둔 기기가 없음. Termux에 올리는 시도는 무겁고 불안정 |
| **Working Copy** (iOS) | 모바일 git 클라이언트 중 최고 수준. 오프라인 브라우징 좋음 | iOS 전용이고 "클라이언트"이지 서버가 아님. PC에서 원격으로 못 씀 |
| **MGit / Termux 기반 앱들** (Android) | 폰에서 레포 clone, 열람 | 서버 기능 없음, UI 오래됨 |
| **Syncthing** | 기기 간 폴더 P2P 동기화, 오프라인 LAN 동기화 잘 됨 | `.git` 폴더를 동기화하면 동시에 손댈 때 레포가 깨질 수 있음. 실제로 한 번 깨먹음 |
| **git bundle + 클라우드 드라이브** | 단순, 어디서나 동작 | 수동, 증분 관리 귀찮음, 고객 코드가 제3자 클라우드에 올라감 |
| **Tailscale** | 어디서든 내 기기끼리 사설망. 설정 쉬움 | 폰에서 Tailscale과 다른 VPN(고객사 VPN)을 동시에 못 켬. 안드로이드는 VPN 슬롯이 하나라 충돌. 이건 이 앱에서도 실제로 부딪힐 문제 |
| **GitHub Codespaces / Gitpod** | 노트북 고장나도 브라우저만 있으면 작업 | 인터넷이 좋아야 함. 제 문제와 정반대 상황에서만 유용 |

## 5. 꼭 있어야 하는 것 3가지와 없어도 되는 것

**꼭 있어야 하는 것**
1. **안정적인 push/pull 수신 (특히 같은 와이파이/핫스팟/USB에서)**. 백그라운드에서 죽지 않고, 끊겨도 레포가 깨지지 않을 것. 이게 안 되면 나머지는 의미 없습니다. 노트북이 폰 핫스팟에 붙어 있을 때 사설 IP로 바로 붙는 경로가 제일 중요합니다(데이터 소모 없음).
2. **보안: 인증 + 저장 데이터 암호화 + 외부 노출 기본 꺼짐**. SSH 키 또는 토큰 인증, 레포별 접근 제한, 폰 분실 시 대비. ngrok은 명시적으로 켰을 때만, 켜져 있다는 표시가 항상 보이게.
3. **멀티 호스트 미러 관리 + 상태 표시**. GitHub/GitLab(셀프 호스팅 포함)/Bitbucket 주소를 붙여넣으면 받고, 와이파이일 때만 갱신(데이터 요금 보호), 원본 대비 앞/뒤 커밋 수를 목록에서 보여줄 것. private 레포 인증(PAT) 지원 필수.

**없어도 되는 것 (최소한 초기에는)**
- 브라우저 레포 탐색의 화려한 기능(코드 하이라이팅, blame, 검색 등). 파일 트리와 README, 최근 커밋 로그 정도면 충분합니다.
- 이슈, PR, 위키 같은 GitHub 흉내 기능. 그건 원래 서비스에서 합니다.
- 폰에서 직접 코드 편집. 폰으로 코딩 안 합니다.
- 팀 공유, 다중 사용자 계정. 철저히 1인용이면 됩니다.
- ngrok 연동은 우선순위 낮음. 같은 망 + Tailscale이면 제 케이스 90%는 해결.

## 6. 그 외에 하고 싶은 말

- 이 앱의 포지션을 "GitHub 대체"가 아니라 **"주머니 속 오프라인 원격 저장소 / 보험"**으로 잡으면 저 같은 사람에게 확실히 꽂힙니다. 마케팅 문구도 "인터넷 없어도 push 하세요" 쪽이 좋겠습니다.
- 안드로이드 VPN 슬롯이 하나라서 Tailscale 경로는 고객사 VPN이나 다른 VPN 앱과 충돌합니다. 온보딩에서 이걸 미리 알려 주면 좋겠습니다. 그리고 노트북이 폰 핫스팟에 붙은 상태(폰이 게이트웨이)에서의 사설 IP 접속을 1급 시나리오로 다뤄 주세요. 노마드에게 가장 흔한 구성입니다.
- 미러의 "원본 따라가기"가 force-push된 원본을 만나면 어떻게 하는지 분명해야 합니다. 원본에서 히스토리가 날아가도 폰에는 남아 있는 것이 아카이브로서의 가치라고 생각합니다. 덮어쓰기 전에 이전 상태를 보존하는 옵션이 있으면 좋겠습니다.
- 폰에 쌓인 내 커밋을 원본으로 대신 올려 주는 기능은 편하겠지만, 고객사 계정 토큰을 폰에 저장하는 셈이라 저는 꺼 둘 것 같습니다. 선택 사항으로만.
- 배터리 사용량을 숫자로 보여 주세요. "지난 24시간 동안 서버가 배터리 3% 사용" 같은 정보가 있으면 계속 켜 둘 용기가 생깁니다.
- 유료라면 일회성 결제 선호합니다. 이미 구독이 너무 많습니다. 다만 데이터가 제 기기 밖으로 안 나간다는 걸 보장하면 돈 낼 의향 있습니다.
