# mobilegit 기획서 (PRD) v1

- 작성: PM
- 대상: 코어 개발자, 안드로이드 UI 개발자, 웹 UI 개발자, QA
- 근거: 사용자 확정 사항, `docs/interviews/round1/` (취합본 + 원문 01~05)
- 사이클: 1차에 이 문서의 기능을 모두 구현한다. 2차는 1차에서 나온 문제와 UI 개선을 반영한다. 기능을 1차와 2차로 나누지 않는다.

## 1. 제품 정의

**한 줄 정의**: 안드로이드 폰을 "주머니 속 두 번째 사본"으로 쓰는 1인용 git 서버 겸 아카이브 앱. 원격 레포를 미러로 보존하고, PC에서는 표준 `git`으로 smart HTTP를 통해 clone/pull/push한다.

**포지셔닝**: GitHub 대체가 아니라 보험이다. 원본이 force-push하거나 레포를 지우거나 비공개로 돌려도 폰에 남은 기록은 지워지지 않는다. 폰이 유일한 사본이 되지 않도록 폰 밖으로 내보내는 경로도 기본으로 제공한다.

**사용자**: 개발자 1명 (본인). 다중 사용자나 팀은 고려하지 않는다.

## 2. 용어

| 용어 | 정의 |
|---|---|
| 미러 | 원격 URL을 원본으로 두는 레포. 읽기 전용이며 clone/fetch/pull만 허용한다. 원본 추적(확인/업데이트)의 대상이다. |
| 로컬 레포 | 서버에서 생성된 레포. push로 생성했거나, 앱에서 빈 레포로 만들었거나, 미러를 분리해서 만든다. push를 허용한다. |
| 확인 (check) | 원격 refs만 조회해 로컬과 비교한다. 객체는 받지 않는다 (`ls-remote` 수준). |
| 업데이트 (update) | 원격에서 객체와 refs를 받아 미러에 반영한다 (fetch). |
| 보존 ref | 업데이트 때문에 사라지거나 덮어써질 ref의 이전 값을 보관한 `refs/archive/...` ref |
| 서버 주소 | PC가 접속하는 `http://<host>:<port>` |

## 3. 기능 목록과 수용 기준

표기: **[확정]**은 사용자가 확정한 기능, **[인터뷰]**는 인터뷰에서 PM 판단으로 추가한 기능이다. 수용 기준(AC)은 QA가 그대로 테스트 케이스로 쓸 수 있는 수준으로 적었다.

### F-01 서버 on/off [확정]
메인 화면의 스위치로 smart HTTP git 서버를 켜고 끈다.
- AC1: 스위치를 켜면 2초 안에 지정 포트(기본 8080, 설정에서 1024~65535로 변경 가능)로 수신을 시작하고, 상단에 상태 알림(포그라운드 서비스)이 뜬다. 알림에는 현재 대표 주소와 ngrok 상태가 표시된다.
- AC2: 스위치를 끄면 새 연결을 거부하고, 진행 중인 전송은 최대 10초 동안 기다린 뒤 종료한다. 알림은 사라진다.
- AC3: 포트가 이미 사용 중이면 스위치는 꺼진 상태로 남고, 원인을 담은 오류 메시지("포트 8080 사용 중")가 표시된다.
- AC4: 표준 git 클라이언트(git 2.30 이상, Windows/macOS/Linux)가 `git clone`, `git fetch`, `git pull`, `git push`를 smart HTTP(protocol v0, v2)로 수행할 수 있다. dumb HTTP와 SSH는 지원하지 않는다.
- AC5: 레포 URL은 `http://<host>:<port>/<name>.git` 형식이고, `.git`을 뺀 `/<name>`도 같은 레포로 처리한다.
- AC6: 서버는 모든 인터페이스(0.0.0.0)에서 수신한다. 따라서 같은 폰의 Termux에서도 `http://127.0.0.1:<port>/`로 접속할 수 있다.
- AC7: 스위치 상태는 앱 프로세스가 죽었다 살아나도 유지된다. 서버가 켜져 있어야 하는데 프로세스가 재시작되면 서버를 다시 띄운다.

### F-02 접속 주소 표시 [확정]
메인 화면에 PC가 접속할 주소를 표시한다.
- AC1: 사용 가능한 주소를 종류별로 모두 표시한다. 종류는 "와이파이" (사설 IP), "핫스팟" (폰이 핫스팟일 때 해당 인터페이스 IP), "Tailscale" (100.64.0.0/10 대역의 VPN 인터페이스 IP), "ngrok" (공개 URL, F-04가 켜져 있을 때만)이다.
- AC2: 대표 주소 하나를 크게 보여 준다. 우선순위는 와이파이 → 핫스팟 → Tailscale → ngrok 순이다. 나머지 주소는 그 아래에 작게 표시한다.
- AC3: 네트워크가 바뀌면 (와이파이 해제, 핫스팟 켬, Tailscale 연결 등) 5초 안에 표시가 갱신된다.
- AC4: 쓸 수 있는 주소가 하나도 없으면 "접속 가능한 네트워크 없음"과 함께 안내를 표시한다. 안내 내용은 와이파이 연결, 핫스팟 켜기, Tailscale 앱 설치/연결이다.
- AC5: Tailscale은 IP만 감지해 표시한다. 앱은 Tailscale을 제어하지 않는다. Tailscale이 감지되지 않으면 "Tailscale 앱을 설치하고 연결하면 모바일 데이터에서도 접속할 수 있습니다"라는 안내 링크를 보여 준다. 안드로이드의 VPN 슬롯은 하나뿐이라 다른 VPN과 동시에 쓸 수 없다는 점도 함께 안내한다.
- AC6: 주소를 탭하면 클립보드에 복사된다.

### F-03 HTTP Basic 인증 [확정 + 인터뷰 보완]
- AC1: 인증은 기본으로 켜져 있다. 계정은 1개(사용자 이름 + 비밀번호)이고, 모든 git 요청과 웹 화면 요청에 적용한다.
- AC2: 첫 실행 때 사용자 이름은 `git`, 비밀번호는 무작위 16자로 생성해 온보딩에서 보여 준다. 설정에서 둘 다 바꿀 수 있고, 비밀번호는 8자 이상이어야 한다.
- AC3: 비밀번호는 평문으로 저장하지 않는다 (솔트를 넣은 느린 해시). 설정 화면에서 "비밀번호 보기"는 제공하지 않고 "재설정"만 제공한다. 첫 실행 때 생성한 비밀번호는 온보딩 화면에서만 보여 주고 복사 버튼을 둔다.
- AC4: 설정에 "인증 끄기" 토글을 둔다. 끄려면 확인 대화상자를 거쳐야 하고, 꺼진 동안 메인 화면에 경고 배지가 표시된다.
- AC5 [인터뷰 04]: 설정에 "같은 네트워크에서 읽기는 인증 없이 허용" 토글을 둔다 (기본 꺼짐). 켜면 clone/fetch와 웹 화면 열람은 인증 없이 허용하고, push는 계속 인증을 요구한다. ngrok을 거쳐 들어온 요청에는 이 옵션이 적용되지 않는다. 수업 중 학생 PC에 자격 증명이 캐시되는 문제를 피하기 위한 옵션이다.
- AC6: 인증 실패가 같은 IP에서 1분 안에 10회를 넘으면, 그 IP를 5분 동안 차단(429 응답)하고 접속 기록에 남긴다.
- AC7: ngrok이 켜져 있으면 인증 끄기(AC4)와 익명 읽기(AC5)를 쓸 수 없다. ngrok을 켜는 순간 두 옵션은 무시되고, 화면에도 비활성으로 표시된다.

### F-04 ngrok 외부 접속 [확정, 기본 꺼짐]
- AC1: 설정의 "외부 접속(ngrok)"은 기본 꺼짐이다. ngrok authtoken을 넣어야 켤 수 있다.
- AC2: 처음 켤 때 경고를 보여 준다. 내용은 "인터넷의 누구나 이 주소에 접근을 시도할 수 있습니다. 인증이 강제로 켜집니다. 모바일 데이터 사용량이 늘 수 있습니다"이며, 사용자가 확인해야 진행한다.
- AC3: 켜면 앱이 직접 터널을 열고, 공개 URL을 F-02 주소 목록과 상태 알림에 표시한다. 서버가 꺼져 있으면 터널도 열지 않는다.
- AC4: ngrok이 켜져 있는 동안 메인 화면 상단에 "외부 공개 중" 배너가 항상 보이고, 배너에서 바로 끌 수 있다.
- AC5: 터널이 끊기면 지수 백오프로 재연결한다 (최대 5분 간격). 상태(연결 중/연결됨/실패 사유)를 설정 화면과 배너에 표시한다. authtoken이 거부되면 재시도하지 않고 "토큰 확인 필요"를 표시한다.
- AC6: authtoken은 F-07과 같은 방식으로 암호화해 저장한다.
- 제약: Tailscale Funnel이나 Cloudflare Tunnel은 지원하지 않는다 (범위 밖 표 참고).

### F-05 레포 목록 [확정]
- AC1: 메인 화면에 모든 레포를 목록으로 보여 준다. 항목마다 이름, 종류 아이콘(미러/로컬), 상태 배지, 마지막 업데이트 시각(미러) 또는 마지막 push 시각(로컬), 용량을 표시한다.
- AC2: 상태 배지는 다음 중 해당하는 것을 하나 이상 표시한다: `업데이트 있음`, `업데이트 중`, `실패`, `원본 없음`, `인증 필요`, `지연`(F-12 AC5), `LFS 누락`(F-24).
- AC3: 정렬은 이름순과 최근 활동순 중에서 고른다. 필터는 전체/미러/로컬/문제 있음 중에서 고른다. "문제 있음"은 실패, 원본 없음, 인증 필요, 지연 배지가 붙은 레포다.
- AC4: 이름으로 검색할 수 있다.
- AC5: 목록 위쪽의 "+" 버튼에서 미러 추가(F-06), 일괄 미러(F-15), 빈 레포 만들기(F-14)를 고른다.
- AC6: 레포가 500개여도 스크롤이 끊기지 않는다 (NFR-성능).

### F-06 미러 추가 [확정 + 인터뷰: 공유 시트, 여러 줄]
- AC1: HTTPS git URL을 붙여넣으면 미러로 등록한다. GitHub, GitLab(셀프 호스팅 포함), Bitbucket, Gitea/Forgejo 등 smart HTTP를 지원하는 호스트라면 모두 된다. `https://github.com/a/b`처럼 `.git`이 없는 URL이나 브라우저 주소(`/tree/main` 등 하위 경로)를 붙여넣으면 레포 URL로 정규화한다 (GitHub, GitLab, Bitbucket 형식).
- AC2: 레포 이름은 원격 레포 이름으로 자동 제안하고, 등록 전에 사용자가 고칠 수 있다. 이름이 겹치면 `<owner>-<repo>`를 제안한다. 이름 규칙은 데이터 모델 6.1을 따른다.
- AC3: 등록 전에 원격에 접근할 수 있는지 확인한다. 인증이 필요하면 "토큰 필요" 상태를 보여 주고 F-07의 자격 증명 입력으로 이어 준다.
- AC4: 등록하면 즉시 전체 미러 받기(모든 브랜치, 태그, 그 밖의 refs, 전체 히스토리)를 시작하고, 진행률을 표시한다. shallow clone은 지원하지 않는다.
- AC5: 첫 받기가 실패해도 미러 항목은 남는다. 상태는 `실패`가 되고 다시 시도할 수 있다. 중간에 끊겨도 레포가 깨진 상태로 남지 않는다 (NFR-무결성).
- AC6 [인터뷰 01, 02]: 다른 앱의 공유 시트에서 텍스트나 URL을 mobilegit으로 보내면 미러 추가 화면이 URL이 채워진 상태로 열린다. 그 화면에서 "추가" 한 번으로 등록이 끝난다.
- AC7 [인터뷰 01]: 입력란에 URL을 여러 줄 붙여넣으면 줄마다 하나씩 일괄 등록한다. 결과는 F-15의 진행 화면에서 보여 준다.
- AC8: 같은 원격 URL이 이미 미러로 등록되어 있으면 "이미 미러됨"을 알리고 기존 레포로 이동하게 한다.
- AC9: 받기 전에 남은 공간이 하한(NFR-저장 공간) 아래면 등록하지 않고 이유를 표시한다.

### F-07 원격 자격 증명(토큰) [확정]
- AC1: 비공개 원격 레포용 자격 증명을 호스트별로 저장한다. 항목은 호스트, 사용자 이름(선택), 토큰이다. 하나의 호스트에 여러 개를 저장할 수 있고, 미러마다 어떤 자격 증명을 쓸지 고른다. 기본값은 해당 호스트의 첫 번째 자격 증명이다.
- AC2: 토큰은 Android Keystore 키로 암호화해 저장한다. 화면에는 앞 4자리만 보여 준다. 백업 내보내기(F-19)에는 넣지 않는다.
- AC3: 자격 증명을 쓰는 미러가 인증 오류(401/403)를 받으면 상태를 `인증 필요`로 바꾸고 알림을 보낸다 (F-12). 알림을 탭하면 자격 증명 편집 화면으로 간다.
- AC4: 쓰는 미러가 있는 자격 증명을 지우려고 하면, 영향을 받는 미러 수를 보여 주고 확인을 받는다.
- AC5: 토큰은 로그, 동기화 이력, 오류 메시지, 원격 URL 표시 어디에도 노출되지 않는다.

### F-08 미러 읽기 전용 [확정]
- AC1: 미러에는 clone/fetch/pull만 허용한다. push는 거부하고, git 클라이언트에 "This repository is a read-only mirror of <URL>. Fork it in the mobilegit app to push." 메시지를 보여 준다.
- AC2: 거부한 push도 접속 기록(F-23)에 남긴다.

### F-09 수동 업데이트 [확정]
- AC1: 레포 상세 화면과 목록 항목의 메뉴에 "업데이트" 버튼이 있다. 누르면 즉시 업데이트를 실행한다. 자동 업데이트 조건(F-10 AC4)은 수동 업데이트에 적용하지 않는다.
- AC2: 실행 중에는 진행 상태를 보여 주고 버튼을 비활성화한다. 같은 레포의 업데이트는 동시에 하나만 돈다.
- AC3: 끝나면 결과를 보여 준다. 성공이면 바뀐 ref 수, 새 커밋 수, 보존 ref 수를, 실패면 사유를 표시한다. 결과는 이력(F-12)에 기록한다.
- AC4: 메인 화면 메뉴에 "모든 미러 업데이트"가 있다. 동시 실행 수는 NFR-원본 예의를 따른다.
- AC5: 업데이트 중에 클라이언트가 같은 레포를 clone해도 오류가 나지 않는다. 클라이언트는 업데이트 전이나 후의 일관된 상태를 받는다.

### F-10 자동 확인과 자동 업데이트, 실행 조건 [확정]
- AC1: 앱은 주기적으로 모든 미러를 "확인"한다. 원격 refs가 로컬과 다르면 `업데이트 있음` 배지를 붙이고 변경된 ref 수를 표시한다. 주기는 설정에서 1시간, 6시간(기본), 12시간, 24시간 중에서 고른다.
- AC2: 설정의 "자동 업데이트"(기본 켜짐)가 켜져 있으면, 확인 결과 변경이 있는 미러를 이어서 업데이트한다. 꺼져 있으면 배지만 붙이고 사용자가 수동으로 업데이트한다.
- AC3: 레포 상세에서 미러별로 "자동 업데이트에서 제외"할 수 있다. 제외해도 확인은 계속 한다.
- AC4: 자동 업데이트 실행 조건으로 "와이파이에서만"(기본 켜짐)과 "충전 중에만"(기본 꺼짐)을 둔다. 조건이 맞지 않으면 업데이트를 미루고, 레포 상세에 "조건 대기: 와이파이 필요"처럼 대기 사유를 표시한다. 확인(check)은 데이터 사용량이 작으므로 "와이파이에서만"이 켜져 있어도 모바일 데이터에서 실행한다. 단, 설정에서 "확인도 와이파이에서만"을 켜면 확인도 미룬다.
- AC5: 서버가 꺼져 있어도 확인과 업데이트는 돈다. 이 작업은 서버 on/off와 무관하다.
- AC6: 주기 작업은 모든 미러를 같은 순간에 실행하지 않는다. 미러마다 무작위 지연(jitter)을 준다 (NFR-원본 예의).
- AC7: 확인이나 업데이트가 실제로 실행된 시각을 기록한다. F-12 AC5의 지연 판단에 이 값을 쓴다.

### F-11 아카이브 보존 [인터뷰: 공통 요구 1위]
원본이 히스토리를 지워도 미러의 기록은 남긴다. 이 앱이 Gitea/Forgejo 미러와 구별되는 핵심 기능이다.
- AC1: 업데이트할 때 원격에서 사라진 ref(브랜치나 태그 삭제)와 fast-forward가 아닌 방식으로 바뀐 ref(force-push, 태그 이동)는, 덮어쓰거나 지우기 전에 이전 값을 `refs/archive/<UTC 시각 yyyyMMdd'T'HHmmss'Z'>/<원래 ref 경로>`에 보존한다. 예: `refs/archive/20261025T031500Z/heads/main`.
- AC2: 보존한 뒤에는 미러의 일반 refs(`refs/heads`, `refs/tags`)가 원본과 같아진다. 즉 원본을 계속 따라가되, 이전 값은 보존 ref에 남는다.
- AC3: 원본이 404가 되거나 비공개로 전환되어 접근할 수 없어도 미러를 지우거나 비우지 않는다. 상태만 `원본 없음`으로 바꾼다 (F-12).
- AC4: 보존이 일어나면 이력에 "force-push/삭제 감지: N개 ref 보존"으로 기록하고 알림을 보낸다.
- AC5: 보존 ref는 git 클라이언트에 노출(advertise)한다. 일반 `git clone`은 heads와 tags만 받으므로 영향이 없다. `git clone --mirror`나 `git fetch origin 'refs/archive/*:refs/archive/*'`로 받을 수 있다. 레포 상세에 보존 ref 개수와 받는 방법을 안내한다.
- AC6: 이 동작은 모든 미러에 항상 적용하고 끄는 옵션을 두지 않는다 (결정 D-3).
- AC7: 보존 ref도 백업 내보내기(F-19)에 포함한다.

### F-12 동기화 이력, 원본 상태, 실패 알림 [확정 + 인터뷰]
- AC1: 미러마다 확인과 업데이트 기록을 남긴다. 기록 항목은 시작 시각, 소요 시간, 트리거(수동/자동/일괄), 결과(변경 없음/성공/실패/조건 대기), 바뀐 ref 목록(이전 SHA → 새 SHA), 새 커밋 수, 보존 ref 수, 실패 사유다. "변경 없음"으로 끝난 확인은 개별로 남기지 않고 마지막 확인 시각만 갱신한다.
- AC2: 레포 상세에 이력을 최신순으로 보여 준다. 레포당 최근 200건을 보관하고, 오래된 것부터 지운다.
- AC3: 실패 사유는 사용자가 읽을 수 있는 문장으로 분류해 보여 준다: `네트워크 오류`, `인증 필요`(401/403), `원본 없음`(404 또는 레포가 없다는 응답), `저장 공간 부족`, `원격 오류`, `시간 초과`. 원문 오류 메시지는 "자세히"에 접어서 보여 준다.
- AC4: 알림 규칙은 다음과 같다. 상태가 바뀔 때만 보낸다 (정상→실패, 정상→원본 없음, 정상→인증 필요, 보존 발생, 실패→복구). 같은 실패가 반복되면 다시 보내지 않는다. 알림 채널은 "동기화 실패"와 "업데이트 완료"(기본 꺼짐) 두 개로 나눠, 사용자가 시스템 설정에서 따로 끌 수 있게 한다.
- AC5 [인터뷰 02 "정직하게 보여 주기"]: 마지막으로 실행된 확인이 설정 주기의 3배보다 오래되었으면 (예: 6시간 주기인데 18시간 넘게 확인이 돌지 않음) 해당 미러와 메인 화면에 `지연` 배지를 붙인다. 설명은 "백그라운드 작업이 제한되어 확인이 지연되었습니다"이고, 배터리 안내(F-22) 링크를 함께 둔다.
- AC6: 레포 상세 상단에 원본 상태를 요약해 보여 준다: 원본 URL, 원본 상태(정상/원본 없음/인증 필요/알 수 없음), 마지막 확인 시각, 마지막 성공 업데이트 시각. 원본 없음 상태면 "이 미러가 남은 사본일 수 있습니다. 내보내기를 권장합니다" 안내와 내보내기 버튼을 둔다.

### F-13 push로 레포 생성 [확정]
- AC1: 존재하지 않는 이름으로 인증된 push가 오면 빈 로컬 레포를 만들고 push를 받는다.
- AC2: 이름이 규칙(6.1)에 맞지 않으면 거부하고 이유를 클라이언트에 메시지로 돌려준다.
- AC3: 익명 읽기 옵션(F-03 AC5)이 켜져 있어도, push와 그로 인한 생성에는 항상 인증이 필요하다. 인증을 끈 상태(F-03 AC4)라면 인증 없이도 생성된다.
- AC4: 생성된 레포는 메인 목록에 즉시 나타난다 (앱이 열려 있으면 실시간 반영).
- AC5: 로컬 레포의 HEAD는 처음 push된 브랜치를 가리킨다. 그 브랜치가 `main`이나 `master`가 아니고 둘 중 하나가 함께 push되었다면 그쪽을 HEAD로 삼는다. 레포 상세에서 기본 브랜치를 바꿀 수 있다.
- AC6: push 중에 연결이 끊겨도 레포가 깨지지 않는다. refs는 원자적으로 갱신된다.

### F-14 앱에서 빈 레포 생성 [확정]
- AC1: 이름과 설명(선택)을 입력하면 빈 로컬 레포를 만든다.
- AC2: 만든 뒤에는 레포 상세로 이동하고, PC에서 쓸 명령 예시를 복사 가능한 형태로 보여 준다: `git remote add phone <URL>` 및 `git push -u phone main`.

### F-15 계정·조직 단위 일괄 미러 [확정]
- AC1: 소스를 고른다: GitHub 사용자, GitHub 조직, GitLab 사용자, GitLab 그룹. GitLab은 기본 `gitlab.com`이고 셀프 호스팅 주소도 넣을 수 있다. 소스에 맞는 F-07 자격 증명을 고르면 비공개 레포까지 목록에 나온다.
- AC2: 원격 API로 레포 목록을 가져와 체크박스 목록으로 보여 준다. 항목마다 이름, 설명, 원격이 제공하는 경우 대략적인 크기, fork 여부, archived 여부를 표시한다. 이미 미러로 등록된 레포는 "등록됨"으로 표시하고 선택할 수 없다.
- AC3: 필터로 "fork 제외"(기본 켜짐)와 "archived 제외"(기본 꺼짐)를 제공하고, "전체 선택"을 둔다.
- AC4: 선택한 크기 합계(아는 경우)와 남은 공간을 함께 보여 준다. 합계가 남은 공간에서 하한을 뺀 값보다 크면 경고한다.
- AC5: 등록하면 대기열에 넣고 NFR-원본 예의의 동시 실행 수만큼 받는다. 진행 화면에 전체 N개 중 완료/실패/대기 수와 레포별 상태를 표시한다. 앱을 닫아도 백그라운드에서 계속 진행한다.
- AC6: 실패한 레포만 골라 "실패한 항목 다시 시도"를 할 수 있다.
- AC7: API 레이트리밋에 걸리면 재시도 가능 시각까지 기다렸다가 이어서 진행하고, 그 사실을 진행 화면에 표시한다.
- AC8: 일괄 등록은 1회성이다. 이후 원격 계정에 새로 생긴 레포를 자동으로 추가하지는 않는다 (범위 밖 표 참고).

### F-16 clone 주소 복사와 QR [확정]
- AC1: 레포 상세에 clone URL을 F-02의 주소 종류별(와이파이/핫스팟/Tailscale/ngrok)로 보여 주고, 각각 복사 버튼을 둔다.
- AC2: "QR" 버튼을 누르면 선택한 주소의 clone URL을 QR로 전체 화면에 크게 띄운다. 이때 화면 밝기를 최대로 올리고 화면 꺼짐을 막는다. 프로젝터에 띄우는 상황을 고려해 URL 텍스트도 큰 글씨로 함께 표시한다.
- AC3: URL이나 QR에 사용자 이름이나 비밀번호를 넣지 않는다.
- AC4: 메인 화면의 서버 주소에도 같은 QR 기능을 둔다. 이 QR은 웹 화면 주소용이다.
- AC5: 레포 상세에 `git clone <URL>` 명령 전체를 복사하는 버튼을 둔다.

### F-17 저장 공간 표시 [확정]
- AC1: 저장 공간 화면에 앱 전체 사용량, 기기 남은 공간, 레포별 용량(큰 순 정렬)을 보여 준다.
- AC2: 레포 목록과 레포 상세에도 레포 용량을 표시한다. 용량은 업데이트나 push가 끝난 뒤 다시 계산한다. 계산이 무겁다면 캐시를 쓰되, 측정 시각을 함께 표시한다.
- AC3: 남은 공간이 하한(NFR-저장 공간)보다 적으면 메인 화면에 경고 배너를 띄우고, 자동 업데이트와 새 미러 받기를 멈춘다. push는 계속 받되, 남은 공간이 받을 데이터 크기보다 작으면 실패시키고 레포를 깨뜨리지 않는다.
- AC4: 저장 공간 화면에서 레포를 탭하면 레포 상세로 이동한다. 지우기는 레포 상세에서 한다.

### F-18 브라우저용 읽기 전용 웹 화면 [확정]
- AC1: 서버가 켜져 있으면 git 서버와 같은 포트의 `/` 경로에서 웹 화면을 제공한다. 인증 규칙은 F-03과 같다 (Basic 인증, 익명 읽기 옵션 반영).
- AC2: 화면 구성은 레포 목록, 레포 홈(파일 트리 + README), 파일 보기, 커밋 로그의 네 가지다 (7.2 참고).
- AC3: 읽기 전용이다. 웹 화면에서 수정, 생성, 삭제, 업데이트를 실행하는 기능은 제공하지 않는다.
- AC4: 브랜치와 태그를 선택할 수 있고, 기본은 HEAD 브랜치다. 보존 ref(`refs/archive/*`)는 선택 목록에 넣지 않는다.
- AC5: README는 `README.md`(Markdown 렌더링), `README`/`README.txt`(고정폭 텍스트) 순서로 찾는다. Markdown 안의 raw HTML과 스크립트는 제거한다 (NFR-보안).
- AC6: 1MB를 넘는 파일과 바이너리 파일은 내용을 표시하지 않고 "표시할 수 없음"과 크기를 보여 준다. "원본 다운로드" 링크를 제공한다.
- AC7: 외부 CDN에서 아무것도 불러오지 않는다. 모든 리소스를 앱이 제공해서 인터넷이 없는 LAN에서도 동작해야 한다.
- AC8: PC 브라우저(Chrome, Firefox, Safari, Edge 최신)와 모바일 브라우저에서 레이아웃이 깨지지 않는다.
- AC9: 데이터는 코어 개발자가 제공하는 읽기 전용 JSON API로 받는다. API 범위는 7.3에 정리했다.

### F-19 백업 내보내기 [확정 + 인터뷰: manifest]
- AC1: 레포 상세의 "내보내기 → git bundle"은 해당 레포의 모든 refs(보존 ref 포함)를 담은 `<name>.bundle` 파일을 만든다. 이 파일은 PC에서 `git clone <name>.bundle`로 복원할 수 있어야 한다.
- AC2: 설정 또는 저장 공간 화면의 "전체 백업(zip)"은 선택한 레포들(기본 전체)을 하나의 zip으로 만든다. zip에는 레포별 `.bundle`과 `manifest.json`이 들어간다. manifest에는 레포 이름, 종류, 원본 URL, 원본 상태, 마지막 업데이트 시각, refs별 SHA, 앱 버전, 내보낸 시각을 담는다.
- AC3: 레포 상세의 "내보내기 → 소스 zip"은 선택한 브랜치의 최신 트리를 `.git` 없이 zip으로 만든다. 코드를 git 없이 전달할 때 쓴다.
- AC4: 저장 위치는 시스템 파일 선택기로 사용자가 고른다 (SD 카드, 클라우드 드라이브 앱 포함). "공유"를 고르면 공유 시트로도 보낼 수 있다.
- AC5: 내보내기는 백그라운드에서 진행하고 진행률을 알림으로 보여 준다. 실패하면 불완전한 파일을 남기지 않는다.
- AC6: 자격 증명, 비밀번호, ngrok authtoken은 어떤 내보내기에도 넣지 않는다.
- AC7: 앱 안으로 가져오기(복원)는 제공하지 않는다. 복원 방법은 레포 상세와 백업 화면에 안내한다: "PC에서 `git clone x.bundle` 후 이 폰으로 push". push하면 레포가 생성되므로(F-13) 별도의 가져오기 기능이 없어도 복원 경로가 닫혀 있지 않다.

### F-20 미러를 로컬 레포로 분리(fork) [확정]
- AC1: 미러 레포 상세의 "로컬 레포로 분리"를 누르면 확인 대화상자를 보여 준다. 내용은 "원본 추적이 중단되고 되돌릴 수 없습니다. push가 가능해집니다"이다.
- AC2: 분리 방식은 두 가지 중에서 고른다. (a) 이 미러를 그대로 로컬 레포로 전환, (b) 미러는 그대로 두고 새 이름의 로컬 레포로 복제. 기본은 (b)다. 미러를 계속 따라가면서 수정본을 따로 두려는 경우(인터뷰 04)를 기본으로 삼았다.
- AC3: 분리된 로컬 레포에서는 push가 가능하고, 확인/업데이트 대상에서 빠진다. 기존 refs, 보존 ref, (a)의 경우 동기화 이력은 그대로 유지한다.
- AC4: 로컬 레포 상세에 "분리 원본: <URL>, <분리 시각>"을 정보로 표시한다. 이 URL로 원격 작업을 하지는 않는다.
- AC5: (b)로 복제할 때 남은 공간이 부족하면 실행하지 않는다.

### F-21 레포 삭제 [필수 관리 기능]
- AC1: 레포 상세의 "삭제"를 누르면 레포 이름을 직접 입력해야 하는 확인 대화상자를 보여 준다.
- AC2: 미러가 `원본 없음` 상태라면 "이 레포는 원본이 없어 복구할 수 없을 수 있습니다"를 추가로 경고하고, 내보내기를 먼저 하도록 권한다.
- AC3: 삭제는 해당 레포 데이터와 이력을 모두 지우고, 사용하던 공간을 반환한다. 진행 중인 clone이 있으면 그 연결을 끊는다.

### F-22 백그라운드 유지, 배터리 최적화 안내, 부팅 후 자동 시작 [인터뷰: 공통 요구]
- AC1: 서버가 켜져 있는 동안 포그라운드 서비스와 상태 알림을 유지한다. 화면이 꺼져도 접속을 받는다 (NFR-백그라운드).
- AC2: 설정의 "부팅 후 서버 자동 시작"(기본 꺼짐)을 켜면, 재부팅 뒤 마지막 서버 상태가 켜짐이었을 때 서버를 다시 시작한다. 자동 확인과 업데이트 예약은 이 설정과 무관하게 재부팅 뒤에도 유지된다.
- AC3: "백그라운드 안내" 화면을 둔다. 이 화면은 다음 내용을 담는다.
  - 현재 배터리 최적화 예외 여부와 시스템 설정으로 바로 가는 버튼
  - 제조사별 추가 안내 (최소: 삼성, 샤오미, 원플러스, 구글 픽셀). 기기 제조사를 감지해 해당 안내를 먼저 보여 준다.
  - 서랍 폰 운영 팁: 충전기에 꽂아 두기, 배터리 보호(충전 상한) 기능 사용 권장
- AC4: 배터리 최적화 예외가 아니면 메인 화면에 작은 경고 칩을 띄우고, 탭하면 안내 화면으로 간다. 사용자가 닫으면 30일 동안 다시 띄우지 않는다.
- AC5: 온보딩에서 이 안내를 한 번 보여 준다 (F-25).

### F-23 접속 기록 [인터뷰 01, 03, 05]
- AC1: 서버가 받은 요청을 기록한다. 항목은 시각, 접속 IP, 경로 종류(와이파이/핫스팟/Tailscale/ngrok/localhost), 레포, 동작(clone·fetch/push/웹), 인증 결과, 응답 결과다.
- AC2: 설정의 "접속 기록" 화면에서 최신순으로 보고, ngrok 경로나 인증 실패만 따로 필터할 수 있다. 최근 2,000건을 보관한다.
- AC3: 비밀번호나 Authorization 헤더 내용은 기록하지 않는다.
- AC4: 로컬 레포 상세에 "마지막 push: 시각, IP"를 표시한다 (인터뷰 04의 "누가 언제 push했나"를 1인용 범위에서 반영).

### F-24 LFS·서브모듈 경고 [인터뷰 01, 02, 05]
- AC1: 업데이트나 push가 끝난 뒤 HEAD 브랜치의 `.gitattributes`에 `filter=lfs`가 있으면 `LFS 누락` 배지를 붙인다. 레포 상세에는 "이 레포는 Git LFS를 쓰지만 LFS 파일은 저장되지 않습니다"라고 안내한다.
- AC2: HEAD 브랜치에 `.gitmodules`가 있으면 레포 상세에 "서브모듈은 함께 보존되지 않습니다"를 안내하고, 서브모듈 URL 목록을 보여 준다. 각 URL 옆에 "미러 추가" 바로가기를 둔다.
- AC3: LFS 포인터 파일은 웹 화면에서 "LFS 파일 (저장되지 않음)"으로 표시한다.

### F-25 첫 실행 온보딩 [인터뷰 05, 01]
- AC1: 첫 실행 때 3~4장의 화면을 보여 준다. 건너뛸 수 있다.
  1. 이 앱이 하는 일과 "폰은 추가 사본, 정기적으로 내보내기를 권장"
  2. **데이터 위치 안내**: 레포는 앱 내부 저장소에 있고, 앱을 지우거나 앱 데이터를 지우면 모든 레포가 사라진다는 점
  3. 생성된 접속 계정(사용자 이름과 비밀번호) 표시와 복사
  4. 알림 권한 요청, 배터리 최적화 안내(F-22)
- AC2: 설정의 "정보" 화면에서 같은 내용을 다시 볼 수 있다.

### 기능 수 요약
- 확정 범위: F-01 ~ F-21 (F-21 삭제는 확정 목록에 없지만 레포 관리에 필수라 넣었다)
- 인터뷰 반영 신규: F-11, F-22, F-23, F-24, F-25 (+ F-06 공유 시트·여러 줄 입력, F-03 익명 읽기, F-12 지연 배지, F-19 manifest)
- 총 25개

### A-02 메인
- 상단: 앱 이름, 서버 on/off 스위치, ngrok "외부 공개 중" 배너(켜졌을 때), 경고 칩(인증 꺼짐, 저장 공간 부족, 배터리 최적화, 지연)
- 주소 카드: 대표 주소(크게) + 기타 주소, 탭하면 복사, QR 버튼(웹 화면 주소), 주소가 없을 때 안내
- 레포 목록: 검색, 정렬, 필터 칩(전체/미러/로컬/문제 있음), 항목(이름, 종류, 배지, 시각, 용량), 항목 롱프레스나 메뉴로 업데이트
- "+" FAB: 미러 추가 / 일괄 미러 / 빈 레포
- 오버플로 메뉴: 모든 미러 업데이트, 저장 공간, 설정
- 빈 상태: "아직 레포가 없습니다" + 세 가지 추가 방법 + PC에서 push로 만드는 명령 예시

### A-07 레포 상세
- 헤더: 이름, 종류, 용량, 배지
- 미러인 경우 원본 상태 카드: 원본 URL, 원본 상태, 마지막 확인, 마지막 성공 업데이트, 대기 사유, "업데이트" 버튼, "자동 업데이트에서 제외" 토글, 자격 증명 선택
- 로컬인 경우 정보 카드: 기본 브랜치 선택, 마지막 push(시각, IP), 분리 원본(있을 때)
- clone 카드: 주소 종류별 URL + 복사, `git clone` 명령 복사, QR
- 경고 카드: LFS, 서브모듈(URL 목록 + 미러 추가), 원본 없음 → 내보내기 권장
- 보존 ref 카드: 개수, 받는 방법 안내 (보존 ref가 1개 이상일 때만)
- 이력 탭: 동기화 이력 목록, 항목을 펼치면 바뀐 ref와 원문 오류
- 메뉴: 내보내기(bundle/소스 zip), 로컬 레포로 분리(미러만), 삭제

### A-10 설정
- 서버: 포트, 사용자 이름, 비밀번호 재설정, 인증 끄기, 같은 네트워크 익명 읽기, 부팅 후 자동 시작
- 외부 접속: ngrok 토글, authtoken, 연결 상태
- 동기화: 확인 주기, 자동 업데이트, 와이파이에서만, 충전 중에만, 확인도 와이파이에서만
- 원격 자격 증명 → A-11
- 백그라운드 안내 → A-12
- 접속 기록 → A-13
- 백업 → A-14
- 정보: 버전, 온보딩 다시 보기, 오픈소스 라이선스

## 6. 데이터 모델 개요

저장소 구현(DB 종류, 스키마 세부)은 코어 개발자가 정한다. 아래는 필요한 정보와 관계다.

### 6.1 Repo
| 필드 | 설명 |
|---|---|
| id | 내부 식별자 |
| name | URL에 쓰는 이름. 규칙 `^[A-Za-z0-9][A-Za-z0-9._-]{0,99}$`, `.git`으로 끝날 수 없음, 대소문자 무시 유일. 계층(`owner/repo`)은 두지 않는다. |
| type | `MIRROR` / `LOCAL` |
| description | 선택 |
| createdAt, createdBy | 생성 시각, 생성 경로(`APP_EMPTY` / `PUSH` / `MIRROR_ADD` / `BULK` / `FORK`) |
| defaultBranch | HEAD가 가리키는 브랜치 |
| sizeBytes, sizeMeasuredAt | 용량 캐시 |
| hasLfs, submoduleUrls | F-24 결과 |
| lastPushAt, lastPushIp | 로컬 레포 |
| forkedFrom | 분리 원본 URL, 분리 시각 (로컬 레포, 선택) |

### 6.2 MirrorSource (Repo가 MIRROR일 때 1:1)
| 필드 | 설명 |
|---|---|
| remoteUrl | 정규화된 HTTPS URL (자격 증명 미포함) |
| credentialId | RemoteCredential 참조 (선택) |
| autoUpdateExcluded | 자동 업데이트 제외 여부 |
| originStatus | `OK` / `GONE` / `AUTH_REQUIRED` / `UNKNOWN` |
| lastCheckAt, lastCheckResult | 마지막 확인 |
| lastSuccessUpdateAt | 마지막 성공 업데이트 |
| pendingChanges | 확인으로 발견한 변경 ref 수 (`업데이트 있음` 배지 근거) |
| waitingReason | 조건 대기 사유 (없음/와이파이/충전/공간) |
| consecutiveFailures | 알림 중복 방지와 백오프 |

### 6.3 SyncEvent (Repo 1:N, 레포당 최근 200건)
startedAt, durationMs, trigger(`MANUAL`/`AUTO`/`BULK`/`INITIAL`), kind(`CHECK`/`UPDATE`), result(`NO_CHANGE`/`SUCCESS`/`FAILED`/`WAITING`), refChanges[{ref, oldSha, newSha, archivedAs}], newCommitCount, archivedRefCount, errorCategory, errorDetail(토큰 제거)

### 6.4 RemoteCredential
id, host, username(선택), token(Keystore로 암호화), label, createdAt

### 6.5 BulkJob / BulkItem
BulkJob: id, source(종류, 계정명, 호스트), createdAt, status
BulkItem: jobId, remoteUrl, repoName, status(`QUEUED`/`RUNNING`/`DONE`/`FAILED`), error

### 6.6 AccessLog (최근 2,000건)
at, clientIp, route(`WIFI`/`HOTSPOT`/`TAILSCALE`/`NGROK`/`LOCALHOST`), repoName, action(`READ`/`PUSH`/`WEB`), authResult(`OK`/`FAILED`/`ANONYMOUS`/`BLOCKED`), status

### 6.7 Settings
| 항목 | 기본값 |
|---|---|
| serverEnabled | false (마지막 값 유지) |
| port | 8080 |
| authEnabled | true |
| username / passwordHash | `git` / 첫 실행 무작위 |
| anonymousReadOnLan | false |
| startOnBoot | false |
| ngrokEnabled / ngrokAuthtoken(암호화) | false / 없음 |
| checkIntervalHours | 6 |
| autoUpdate | true |
| updateWifiOnly | true |
| updateChargingOnly | false |
| checkWifiOnly | false |
| storageFloorBytes | 1 GB |
| notifyOnSuccess | false |
| batteryHintDismissedAt | 없음 |

### 6.8 레포 데이터
- 레포마다 bare git 레포 하나. 위치는 앱 내부 저장소로 고정한다 (외부/SD 저장 위치 선택은 범위 밖).

## 7. 웹 화면 (읽기 전용)

### 7.1 원칙
- 단순하게 만든다. 목록, 트리, README, 파일 보기, 커밋 로그가 전부다. 구문 강조, blame, diff, 검색은 없다.
- 외부 리소스를 쓰지 않는다 (F-18 AC7). 페이지 하나당 전송량을 작게 유지한다.
- 모든 화면 상단에 앱 이름, 레포 경로(빵부스러기), 현재 브랜치 선택을 둔다.

### 7.2 화면
| ID | 화면 | 요소 |
|---|---|---|
| W-01 | 레포 목록 | 이름, 종류(미러/로컬), 설명, 마지막 업데이트/push 시각, 원본 상태(미러), LFS 표시. 이름 필터 입력 |
| W-02 | 레포 홈 | clone URL(현재 접속한 호스트 기준) + 복사 버튼, 브랜치/태그 선택, 최신 커밋 한 줄(메시지, 작성자, 시각, 짧은 SHA), 루트 파일 트리, README 렌더링. 미러면 원본 URL과 "읽기 전용 미러" 표시 |
| W-02b | 디렉터리 보기 | W-02와 같은 트리 화면으로 하위 경로를 보여 준다 |
| W-03 | 파일 보기 | 경로, 크기, 텍스트 내용(줄 번호), 1MB 초과·바이너리·LFS 포인터 처리(F-18 AC6, F-24 AC3), 원본 다운로드 |
| W-04 | 커밋 로그 | 선택한 브랜치의 커밋 목록(짧은 SHA, 메시지 첫 줄, 작성자, 시각), 페이지당 50개 페이지네이션. 경로를 지정하면 해당 경로의 이력 |
| W-E | 오류 | 없는 레포/경로/브랜치(404), 빈 레포("아직 커밋이 없습니다" + push 명령 예시) |

### 7.3 데이터 API (코어 ↔ 웹 계약 범위)
URL과 응답 형식은 코어 개발자와 웹 UI 개발자가 합의해 `docs/`에 따로 정리한다. 필요한 데이터는 다음과 같다.
- 레포 목록 (W-01 필드)
- 레포 메타 + refs 목록 (브랜치, 태그, HEAD)
- 트리 조회 (ref, 경로) → 항목(이름, 종류, 크기)
- blob 조회 (ref, 경로) → 텍스트 또는 "표시 불가" 정보, raw 다운로드
- README 조회 (ref) → 원문 (Markdown 렌더링을 서버와 클라이언트 중 어디서 할지는 두 개발자가 정한다. 단, 정화(sanitize)는 필수)
- 커밋 로그 (ref, 경로 선택, 페이지)
- 모든 API는 GET만 제공하며, git 엔드포인트와 같은 인증을 쓴다.

## 8. 비기능 요구

### NFR-백그라운드
- 서버가 켜져 있는 동안 포그라운드 서비스로 유지하고, 화면이 꺼져 있어도 접속을 받는다. 이를 위해 필요한 wake lock과 Wi-Fi lock은 서버가 켜져 있는 동안에만 쥔다.
- 검증 기준 (QA): 배터리 최적화 예외를 등록한 갤럭시 S 시리즈와 픽셀 기기에서, 화면을 끈 채 8시간 동안 30분마다 clone이 성공해야 한다. 예외를 등록하지 않은 상태의 결과도 함께 기록해, 안내 문구(F-22)에 반영한다.
- 자동 확인과 업데이트는 OS의 주기 작업 스케줄러에 맡겨 앱 프로세스가 없어도 실행되게 한다. 정확한 실행 시각은 보장하지 않으며, 그 대신 지연 사실을 숨기지 않는다 (F-12 AC5).
- targetSdk는 최신 Play 정책을 따르고, 포그라운드 서비스 유형 선언과 권한도 그에 맞춘다. 서비스 유형 선택은 코어 개발자가 정한다.

### NFR-보안 기본값
- 기본 상태: 서버 꺼짐, 인증 켜짐, 익명 읽기 꺼짐, ngrok 꺼짐.
- ngrok이 켜져 있으면 인증을 강제한다 (F-03 AC7).
- 원격 토큰과 ngrok authtoken은 Android Keystore 기반으로 암호화한다. 접속 비밀번호는 해시로만 저장한다.
- 비밀 값(토큰, 비밀번호, Authorization 헤더)은 로그, 이력, 오류 메시지, 내보내기, 크래시 리포트에 남기지 않는다.
- 웹 화면: Markdown의 raw HTML과 스크립트를 제거한다. 파일 내용은 항상 이스케이프한다. `Content-Security-Policy`로 인라인 스크립트와 외부 리소스를 막는다. raw 다운로드는 `Content-Disposition: attachment`와 `X-Content-Type-Options: nosniff`로 보낸다.
- 경로 조작 방지: 레포 이름 규칙(6.1) 밖의 요청은 파일 시스템에 닿기 전에 거부한다.
- 앱 데이터의 Android 자동 백업(클라우드)은 끈다. 레포와 토큰이 Google 백업으로 나가지 않게 하기 위해서다.
- 서버는 평문 HTTP다. LAN, Tailscale(WireGuard 암호화), ngrok(공개 구간 HTTPS) 각각의 노출 범위를 설정 화면 도움말에 적는다. LAN 평문 HTTP에서는 Basic 인증 정보가 같은 네트워크의 다른 기기에 노출될 수 있다는 점을 안내한다. HTTPS 자체 서버는 범위 밖이다 (9장).

### NFR-저장 공간
- 남은 공간 하한은 1GB이고, 설정에서는 숨김 값으로 둔다. 남은 공간이 하한 아래면 새 미러 받기, 자동 업데이트, 분리 복제를 시작하지 않는다 (F-17 AC3).
- 업데이트, push, 내보내기 중에 공간이 부족해 실패하면 불완전한 객체나 임시 파일을 정리하고 레포는 이전 상태로 남긴다.
- 미러는 full mirror(전체 히스토리, 모든 refs)만 지원한다.
- 저장소 정리(gc/repack)는 사용자 기능으로 두지 않는다. 코어 개발자가 필요하다고 판단하면 자동으로 실행한다 (예: 충전 중 유휴 시간).

### NFR-동시 접속과 성능
- 기준 기기: 중급 기기 (갤럭시 A5x 계열, RAM 6GB)
- 동시 접속: 같은 와이파이에서 클라이언트 30대가 50MB 레포를 동시에 clone할 때 모두 성공해야 한다 (인터뷰 04 수업 시나리오). 처리 한도를 넘는 요청은 실패시키지 않고 대기열에서 기다리게 한다. 대기 중에 git 클라이언트가 시간 초과하지 않도록 합리적인 상한을 둔다.
- 큰 레포: pack 크기 2GB 레포의 clone과 미러 업데이트가 메모리 부족 없이 끝나야 한다. 메모리 사용량이 레포 크기에 비례해 늘어나지 않는 방식을 코어 개발자가 고른다 (인터뷰 05의 JGit 메모리 우려).
- 메인 화면은 레포 500개에서도 1초 안에 표시하고 스크롤이 매끄러워야 한다. 용량 계산 같은 무거운 작업은 UI 스레드에서 하지 않는다.
- 웹 화면의 트리 화면과 로그 첫 페이지는 LAN에서 1초 안에 응답한다 (레포 1GB 기준).

### NFR-원본 예의 (rate limit)
- 미러 확인과 업데이트의 동시 실행은 최대 2개다. 일괄 미러도 이 한도를 따른다.
- 주기 실행 시 미러마다 무작위 지연을 준다 (주기의 10% 이내).
- 실패한 미러에는 지수 백오프를 적용한다 (최대 24시간). 수동 업데이트는 백오프를 무시한다.
- 원격 API(일괄 미러)의 레이트리밋 응답 헤더를 존중한다.

### NFR-무결성
- clone, push, 업데이트, 분리 중 어느 시점에 연결이 끊기거나 앱이 죽어도 레포는 이전 상태나 완료 상태 중 하나로 남아야 한다. refs는 원자적으로 갱신한다.
- 같은 레포에 대한 push와 업데이트·분리·삭제는 서로 배타적으로 처리한다.

### NFR-기타
- 최소 Android 버전: 코어 개발자 제안을 받아 결정한다 (PM 기준은 Android 8.0 이상).
- 언어: 1차는 한국어 UI. 문자열은 리소스로 분리해 두어 이후 영어 추가가 가능하게 한다.
- 접근성: 모든 아이콘 버튼에 콘텐츠 설명을 단다. 배지는 색과 함께 텍스트로도 구분한다.
- 네트워크: 서버는 IPv4를 필수로 지원한다. IPv6는 동작하면 좋지만 주소 표시 대상에서는 뺀다.

| 접속 진단 (AP 격리 감지) | 제외 | 폰 혼자서는 신뢰성 있게 판별할 수 없다. 주소가 없을 때의 안내(F-02 AC4)와 백그라운드 안내에 "같은 와이파이인데 접속이 안 되면 핫스팟을 사용"이라는 팁을 넣는다. |
| 배터리 사용량 수치 표시 | 제외 | 앱별 정확한 측정 API가 없다. 시스템 배터리 화면으로 안내한다. |
| Tailscale 제어, Tailscale Funnel, Cloudflare Tunnel | 제외 | 사용자 결정 (Tailscale은 IP만 표시, 외부 노출은 ngrok만). |
| HTTPS 자체 인증서 서버 | 제외 | LAN에서 인증서를 배포하고 신뢰시키는 과정이 복잡하다. Tailscale과 ngrok 경로가 암호화를 제공한다. 위험은 도움말로 안내한다 (NFR-보안). |
| USB 연결 (adb reverse 등) | 제외 | 핫스팟 사설 IP로 같은 효과를 낸다 (인터뷰 03). |
| 라이선스 기록, 릴리스 첨부파일 보관 | 제외 | git 밖의 메타데이터는 범위 밖이다. LICENSE 파일은 레포 안에 있으므로 웹 화면에서 볼 수 있다. |
| 홈 화면 위젯 | 제외 | 상태 알림으로 충분하다 (인터뷰 05). |

## 11. 주요 결정 (팀 공유용)

| ID | 결정 | 이유 |
|---|---|---|
| D-1 | 포지셔닝은 "서버"보다 "주머니 속 두 번째 사본(아카이브)"을 앞에 둔다. | 인터뷰 5명 중 4명이 이 가치를 핵심으로 꼽았다. |
| D-2 | 레포 이름은 계층 없는 평면 구조로 둔다 (`/<name>.git`). | 주소를 짧게 유지하기 위해서다 (인터뷰 04). 이름이 겹치면 `<owner>-<repo>`를 제안한다. |
| D-3 | 보존(F-11)은 모든 미러에 항상 적용하고, 끄는 옵션을 두지 않는다. | 아카이브가 존재 이유다. 옵션을 두면 테스트 경우의 수만 늘어난다. 용량 증가는 force-push가 일어난 경우로 한정되므로 감수한다. |
| D-4 | 자동 확인은 `ls-remote` 수준의 가벼운 조회이고, 실제 받기(업데이트)만 와이파이·충전 조건을 따른다. | 모바일 데이터에서도 "업데이트 있음"을 알 수 있게 하면서 데이터 요금을 보호한다. |
| D-5 | 익명 읽기는 옵션(기본 꺼짐)으로만 두고, ngrok 경로에서는 항상 인증한다. | 사용자 결정(Basic 기본 켬)과 강사 요구 사이의 절충이다. |
| D-6 | 분리(F-20)의 기본은 "새 로컬 레포로 복제"다. | 미러를 계속 따라가면서 수정본을 따로 갖고 싶은 경우(인터뷰 04)가 더 흔하다. 전환이 필요하면 선택할 수 있다. |
| D-7 | 앱 안 가져오기(복원)는 만들지 않고 "bundle clone → push"로 복원한다. | push 생성 기능이 이미 복원 경로를 제공한다. |

## 12. 미정 사항 (코어 개발자 답변 필요)
- 최소 Android 버전과 포그라운드 서비스 유형 (NFR-기타, NFR-백그라운드)

- 웹 API 형식과 README 렌더링 위치 (7.3)
