## 결함

### QA2-01 끊긴 연결이 "원본 없음"으로 분류됨 (중간, 코어)
- 현상: 원본 서버가 응답 없이 연결을 닫으면 업데이트 결과가 "원본 없음"이 되어 목록 배지와 원본 없음 알림이 나간다. 그 뒤에는 연결 거부(진짜 네트워크 오류)가 나도 "원본 없음"이 유지된다.
- 원인: `MirrorEngine.kt` 220행에서 오류 원문에 `"not found"`가 있으면 ORIGIN_GONE이다. okhttp의 끊긴 연결 오류(`unexpected end of stream … \n not found: size=0`)가 여기에 걸린다. 또 같은 줄과 221행의 `Regex("\b404\b")`, `Regex("\b40[13]\b")`는 일반 Kotlin 문자열이라 `\b`가 백스페이스 문자가 되어 절대 맞지 않는다 (`"\\b404\\b"`나 raw string이어야 함). `Sync.kt` 305행의 `else -> mir.originStatus`가 다음 네트워크 오류에서도 GONE을 유지한다.
- 재현:
  1. PC에서 `python docs/qa/round1/tools/origin_server.py <root>`를 켜고 `adb reverse tcp:9418 tcp:9418`.
  2. `http://127.0.0.1:9418/<repo>.git`을 미러로 추가한다.
  3. PC 서버만 끈다 (adb reverse는 둔다. 폰 쪽 연결은 받아지고 바로 끊김).
  4. 상세에서 지금 업데이트 → 결과 "원본 없음", 알림도 원본 없음.
  5. adb reverse까지 지운 뒤 다시 업데이트 → 연결 거부인데도 "원본 없음" 그대로.
- 기대: 3~4는 "업데이트 실패 · 네트워크 오류". 원본 없음은 404 또는 NoRemoteRepository일 때만.

### QA2-02 설정의 "push만" 설명이 ngrok 동작과 반대 (중간, 안드로이드 UI)
- 현상: 설정 비밀번호 요구 아래 설명(`settings_auth_push_sub`)이 "push와 ngrok, 폰 안(127.0.0.1)은 계속 비밀번호가 필요해요"라고 한다. R2-06 AC4와 코어(`GitServer.kt` 183행 `anonymousOk = viaNgrok || …`)는 push만일 때 ngrok 경로의 읽기를 비밀번호 없이 허용한다. 위험 조합에서는 "비밀번호 없이 공개 중" 경고 바로 밑에 이 문장이 나와 서로 모순된다.
- 재현: 설정 → 비밀번호 요구 "push만" → 아래 설명을 읽는다. ngrok을 켜고 "그래도 진행"을 고르면 경고와 이 설명이 함께 보인다 (샷 19).
- 기대: ngrok이 와이파이·Tailscale과 같은 규칙을 따른다는 문장. 예: "clone과 웹 화면은 비밀번호 없이 열려요 (ngrok 포함). push와 폰 안(127.0.0.1)은 비밀번호가 필요해요."

### QA2-03 위험 조합에서 터널이 실패해도 배너 제목이 "비밀번호 없이 공개 중" (낮음, 안드로이드 UI)
- 현상: 비밀번호 끄기(또는 push만) + ngrok 상태에서 토큰이 거부되면 배너 본문은 토큰 거부 안내인데 제목은 "비밀번호 없이 공개 중"이다. 실제로는 공개되지 않았다. 1차 QA-07에서 정한 "배너 제목은 터널 상태를 따른다"와 어긋난다.
- 재현: 설정 → 비밀번호 요구 "끄기" → ngrok에 가짜 토큰을 넣고 켜기 → "그래도 진행" → 메인 배너 (샷 20).
- 기대: 실패면 실패 제목(예: "외부 공개 실패")에 위험 조합 표시를 덧붙임.

### QA2-04 "외부 공개는 꺼진 채로 다시 시작했어요"가 상태 알림에 없음 (낮음, 코어 + 안드로이드 UI)
- 현상: ngrok이 켜진 채 앱을 업데이트하면 ngrok은 꺼진 채 다시 시작하지만(통과), 안내는 앱을 열었을 때의 앱 안 배너에만 있다. 상태 알림은 "서버가 꺼져 있어요 / 앱을 열면 서버가 다시 켜져요"뿐이다. R2-05 AC4는 상태 알림에 한 번 보여 주라고 한다.
