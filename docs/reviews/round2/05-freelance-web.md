# 2차 리뷰 05 — 프리랜서 웹 개발자

리뷰어: 고객사 10곳의 웹사이트를 맡는 프리랜서. 카페와 고객사를 옮겨 다니며 노트북과 폰만으로 일함. 웹 UI는 GitHub·Vercel 대시보드 수준을 기준으로 봄.
근거: `docs/qa/round2/screenshots/` 01~30 (번호로 인용).

## 첫인상

"폰 하나로 고객사 레포 백업과 PC→폰 push가 된다"는 약속은 저한테 정확히 필요한 것입니다. 고객사가 GitHub 레포를 정리하거나 외주 개발자가 force-push를 해도 기록이 남는다는 건 실제로 돈이 되는 기능입니다. 06·07에서 그 기능이 git을 아는 사람의 언어(브랜치, SHA, `old → new`)로 보여서 바로 믿음이 갔습니다.

웹 화면(08~11)은 GitHub 레포 페이지를 닮아서 처음 열어도 헤매지 않았습니다. 다만 디테일에서 "잘 만든 사내 도구" 수준에 머뭅니다. 한국어 줄바꿈, 좁은 사이드바 안의 코드 블록, 같은 개념에 붙은 이름 서너 개 같은 것들입니다. 고객에게 이 화면을 보여 줄 일은 없지만, 매일 열어 볼 화면이니 이 정도는 다듬어 줬으면 합니다.

## 좋은 점

- **카페 와이파이 경고(14)**: "카페 같은 공용 와이파이에서는 Tailscale을 쓰세요"는 딱 제 상황입니다. 주소 옆 복사·QR 버튼 배치도 좋습니다.
- **상태 배지(01~04, 26~28)**: 히스토리 바뀜, 실패, 원본 없음, 지연을 아이콘과 색으로 구분해서 목록을 훑을 때 바로 들어옵니다. "6시간 주기인데 3일째 확인 못 함"(04)은 숫자로 말해 줘서 좋습니다.
- **동기화 이력의 변화 종류(06)**: 칩과 `main 12e8ab8 → 4aa4393` 형식이 git log에 익숙한 눈에 딱 맞습니다.
- **보존 기록과 fetch 명령(07, 08)**: 사라진 커밋을 PC로 받는 명령을 복사 버튼과 함께 바로 줍니다. 커밋 메시지와 날짜까지 있어서 무엇이 날아갔는지 알 수 있습니다.
- **웹 반응형(09)**: 390px에서 표가 카드로 바뀌고 가로 스크롤이 없습니다. 폰 브라우저로 볼 일이 많은데 깔끔합니다.
- **SHA마다 복사 버튼(08)**: 제가 실제로 하는 행동(SHA 복사 → 터미널)을 그대로 지원합니다.
- **분리 시트(16)**: "남는 것 / 바뀌는 것" 2단 비교가 명확하고 되돌릴 수 없다는 경고가 제자리에 있습니다.
- **위험한 확인창(18, 25)**: 강조 버튼이 "취소"이고, 위험한 선택은 빨간 텍스트 버튼으로 한 단계 아래에 있습니다.
- **새 로컬 레포 안내(15)**: 명령 두 줄, 핫스팟·USB 테더링 대안, VS Code 경로, bash와 PowerShell 버전이 다 있습니다. 고객사 망에서 와이파이를 못 쓸 때 바로 써먹을 수 있습니다.
- **정직한 알림(21, 30)**: "외부 공개는 꺼진 채로 다시 시작했어요", "ngrok: 토큰 확인 필요"처럼 짧고 정확합니다.

## 헷갈리거나 불편한 점

- **메인 상단이 너무 무겁습니다(01~04)**: 서버 카드, 배터리 배너, 정렬, 요약 줄, 검색, 칩까지 오고 나서야 레포 목록이 시작됩니다. 첫 레포가 화면 중간 아래에 옵니다. 배터리 배너는 닫기 전까지 화면의 1/4을 차지합니다.
- **배너 위치가 들쭉날쭉합니다**: 배터리 배너는 서버 카드 아래(01), ngrok 실패·재시작 배너는 서버 카드 위(20, 21b), 백그라운드 멈춤 배너는 정렬 줄 아래(05)에 있습니다. 경고가 어디서 나올지 예측할 수 없습니다.
- **실패 시각이 잘립니다(02, 26, 28)**: "업데이트 실패 · 네트워크 오류 · 방…"에서 정작 "언제부터"가 잘립니다. 원본 없음(03)은 다 보이니 실패 행만 손해입니다.
- **FAB가 행 내용을 가립니다(04, 20, 21b, 26)**: "레포 추가" 버튼이 용량과 시각을 덮습니다(`1.`, `3.0 K`). 목록 아래 여백이나 스크롤 시 축소가 필요합니다.
- **ngrok 설정이 이상한 곳에 있습니다(29)**: "밖에서 접속하기 (ngrok)"가 설정 맨 아래, 버전·라이선스가 있는 "정보" 묶음 뒤에 있습니다. 보안 설정은 위쪽 "서버" 근처에 있어야 합니다. 이미 설정 화면인데 "설정에서 authtoken을 확인하세요"라고 안내하는 것도 어색합니다(20, 29).
- **"push만" 모드 이해(19, 29b)**: 설명을 두 번 읽어야 "push할 때만 비밀번호를 묻는다"는 뜻인 걸 알았습니다. 세그먼트 라벨만 보면 "push만 허용"으로 읽힙니다.
- **확인 주기 대화상자(22)**: 라디오를 누르면 바로 적용되는지 "닫기"로 저장되는지 알 수 없습니다. "자동 업데이트 조건은 아래 스위치에서 바꿔요"는 대화상자에 가려서 그 스위치가 보이지 않습니다.
- **알림 아이콘이 기본 안드로이드 로봇입니다(17, 21, 30)**: 알림 목록에서 mobilegit을 찾기 어렵고, 완성도가 떨어져 보입니다.
- **고객사 10곳 관점의 아쉬움**: 레포가 늘면 고객사별로 묶거나 태그를 달고 싶습니다. 지금은 이름 검색과 미러/로컬 칩만 있습니다(01). 이번 범위 밖이라면 다음 사이클 후보로 남겨 주세요.

## 시각과 레이아웃 문제 (웹 08~11 중심)

### 08 보존 기록 표 (데스크톱)
- 열 너비 배분이 어색합니다. "보존된 커밋"과 "지금 원본" 사이에 빈 공간이 크고, 마지막 동작 열(커밋 로그 / 파일 보기)에는 헤더가 없습니다.
- "지금 원본" 열에서 `4aa4393`은 작은 고정폭 글꼴이고 "원본에 없음"은 일반 회색 글꼴입니다. 같은 열의 기준선과 크기가 다릅니다. 보존된 커밋 쪽 SHA처럼 칩과 복사 버튼을 쓰면 일관됩니다.
- 그룹 제목 "오후 4:35 · 3개"에 공백이 두 칸 들어갑니다(09도 같음).
- "PC로 받기" 카드 제목이 본문과 굵기가 거의 같아 제목처럼 안 보입니다. 앱 07의 같은 카드는 굵은 제목입니다.

### 09 보존 기록 (390px)
- 카드 전환은 잘 됐습니다. 다만 fetch 명령이 `'refs/` / `archive/*'`처럼 토큰 중간에서 끊깁니다. 코드 블록은 줄바꿈 대신 가로 스크롤(`white-space: pre; overflow-x: auto`)이 맞습니다. 복사해서 쓰니 가독성보다 정확성이 중요합니다.
- "지금 원본 원본에 없음"은 라벨과 값이 붙어 읽힙니다. 라벨 뒤에 콜론이나 구분 스타일이 필요합니다.

### 10 레포 홈
- 오른쪽 사이드바 폭이 좁은데 코드 블록 세 개(URL, clone, fetch)가 쌓여 있습니다. `http://`가 혼자 한 줄에 남고 URL이 세 줄로 쪼개집니다.
- 사이드바 본문에서 한국어가 글자 단위로 끊깁니다: "브랜치·태 / 그 3개", "보존 / 된 기록 보기"(링크까지 끊김), "앱에 / 서". `word-break: keep-all`과 URL에만 `overflow-wrap: anywhere`를 주면 거의 해결됩니다. 11의 경고 카드("LFS 파일 / 은")도 같은 문제입니다.
- 코드 탭 사이드바에 보존 기록 fetch 명령까지 넣으니 정보가 넘칩니다. 사이드바는 "보존된 기록 3개 →" 링크 한 줄이면 됩니다. 명령은 08 탭에 이미 있습니다.
- 페이지 아래 절반이 빈 회색입니다. 왼쪽 열은 README에서 끝나고 사이드바만 길게 내려갑니다. 사이드바 내용을 줄이면 균형이 맞습니다.
- 제목 아래 "업데이트 4분 전"과 정보 패널 "마지막 업데이트 4분 전"이 중복됩니다.
- 상단의 "clone 주소" 버튼(08)과 사이드바 "PC에서 clone" 블록이 같은 일을 합니다. 둘 중 하나만 있어도 됩니다.

### 11 LFS 레포
- 헤더 배지 "LFS 파일 없음"은 "이 레포는 LFS를 안 쓴다"로 읽힙니다. 실제 뜻은 반대(LFS를 쓰지만 실제 파일은 없음)입니다. "LFS 포인터만"이 정확합니다.
- 한 화면에 LFS 표현이 네 개 나옵니다(배지, 경고 카드, 받는 범위, LFS 행). 경고 카드 하나와 정보 행 하나면 충분합니다.
- 파일 목록의 `logo.psd 130 B`에 아무 표시가 없습니다. 디자이너 PSD가 130바이트일 리 없으니 누르면 포인터 텍스트가 나올 겁니다. 파일 행에 "LFS 포인터" 태그를 붙여 주세요. 웹에서 가장 실용적인 개선입니다.
- 로컬 레포 정보 패널의 "받는 범위: push된 브랜치·태그"는 어색합니다. 로컬에는 "받는" 개념이 없으니 이 행은 빼도 됩니다.

### 공통 (웹)
- 헤더 태그라인 "폰 속 git 서버 · 웹에서는 보기만 할 수 있어요"와 푸터 문구가 같은 말을 두 번 합니다.
- 레포 목록으로 돌아가는 경로가 로고 하나뿐입니다. 레포 이름 앞에 `레포 / design-tokens` 같은 브레드크럼이 있으면 좋겠습니다.

### 앱 쪽 레이아웃
- 요약 줄이 두 줄로 넘어갈 때 "· 마지막 확인 1시간 전"처럼 구분점이 둘째 줄 맨 앞에 남습니다(04).
- 칩 줄이 오른쪽에서 잘립니다. "주의 필요 13"의 "13"이 화면 끝에 걸리고(05), 스크롤된다는 힌트(페이드)가 없습니다.
- 13의 "확인 주기" 값이 "자동 업데이트 꺼짐 · 확인만 해요 · 6 / 시간"으로 숫자와 단위 사이에서 끊깁니다.

## 가장 먼저 고칠 것 3가지

1. **웹 줄바꿈 정리 (08~11)**: 본문에 `word-break: keep-all`을 주고, 코드 블록은 줄바꿈 대신 가로 스크롤로 바꾸고, 10의 사이드바에서 fetch 명령은 빼고 링크만 남기세요. CSS 몇 줄로 웹 화면의 인상이 가장 크게 달라집니다.
2. **LFS 표시 바로잡기 (11)**: 헤더 배지를 "LFS 포인터만"으로 바꾸고, 같은 화면의 LFS 표현 네 개를 둘로 줄이고, 파일 목록의 포인터 파일에 태그를 붙이세요. 지금 배지는 뜻이 반대로 읽힙니다.
3. **ngrok 용어와 위치 통일 (18, 20, 25, 29)**: "외부 공개 / 외부 접속 / 밖에서 접속하기"를 하나로 정하고, ngrok 영역을 설정의 "서버" 근처로 옮기세요. 비밀번호 없이 인터넷에 노출되는 기능인데 이름이 셋이고 설정 맨 아래 숨어 있는 건 위험합니다.
