# 2차 리뷰: 7년 차 안드로이드 개발자

리뷰어: 안드로이드 앱 개발 7년 차. 회사 레포 여러 개와 사이드 프로젝트를 다룬다. 출퇴근 지하철에서 폰으로 코드를 자주 본다.
근거: `docs/qa/round2/screenshots/` 32장. 아래 번호는 파일 앞 번호다.

## 첫인상

"force-push로 날아간 기록을 폰이 대신 들고 있어 준다"는 핵심이 이번 사이클에서 화면으로 보이기 시작했다. 06의 동기화 이력에서 `main 12e8ab8 → 4aa4393`과 "히스토리 바뀜"을 보고, 07에서 사라진 커밋 메시지와 `git fetch ... 'refs/archive/*:refs/archive/*'`까지 한 번에 가는 흐름은 개발자가 바로 이해한다. 내가 원하던 그 기능이다.

반면 메인 화면은 아직 무겁다. 배터리 배너, 서버 카드, 요약 줄, 검색, 칩까지 지나야 첫 레포가 보인다(01). 지하철에서 한 손으로 열었을 때 첫 화면에 레포가 3.5개밖에 안 보이는 건 아쉽다. 전체적으로 Material 3 톤은 깔끔하고 일관된 편이라 "개인 프로젝트 티"는 많이 줄었다.

## 좋은 점

- **상태 구분이 명확해졌다.** 실패(02, 26), 원본 없음(03, 27), 지연(04), 히스토리 바뀜(01)이 문구, 색, 아이콘으로 각각 다르다. 특히 "6시간 주기인데 3일째 확인 못 함"(04)은 숫자 두 개로 왜 문제인지 설명해서 좋다. 28에서 원본 없음 상태에서 네트워크 오류가 나면 실패로 바뀌는 것도 맞는 판단이다.
- **동기화 이력의 변화 종류 칩(06).** 브랜치 삭제됨 / 새 브랜치·태그 / 히스토리 바뀜 / 새 커밋 / 태그 이동됨을 ref 이름, SHA 화살표와 같이 보여 준다. `git fetch` 출력의 `+ ... (forced update)`를 사람 말로 번역한 느낌이라 바로 읽힌다.
- **보존 기록 화면(07, 08, 09).** 시각별 묶음, 원래 커밋 메시지, "지금 원본" 값이 같이 있어서 "뭐가 없어졌고 지금은 뭐가 있나"를 비교할 수 있다. 웹 390px(09)에서 표를 카드로 바꾼 것도 잘했다. 가로 스크롤 없다.
- **위험한 공개 조합의 방어(18, 25, 20, 29, 29b).** 기본 버튼이 "취소"이고, 안전한 대안("읽기·쓰기로 바꾸고 공개", "외부 공개 끄고 바꾸기")을 두 번째에, 위험 선택은 빨간 텍스트 버튼으로 맨 아래 둔 순서가 정석이다. 재시작 뒤 외부 공개를 꺼 둔 것(21, 21b)도 보안 감각상 맞다.
- **토큰 안내(13, 24).** "Android 키스토어로 암호화해 저장, 백업에는 넣지 않아요"는 개발자가 제일 먼저 궁금한 걸 짧게 답한다.
- **분리 시트(16).** "남는 것 / 바뀌는 것" 2열 비교와 "되돌릴 수 없어요"가 결정을 돕는다. 권장 옵션이 기본 선택이라 좋다.
- **새 로컬 레포 안내(15).** `git remote add phone ...` 두 줄로 끝나고, LFS는 `GIT_LFS_SKIP_PUSH=1`을 bash/PowerShell로 나눠 준다. 실제로 써 본 사람이 만든 안내다.
- **저장 공간(23).** "방금 기준이에요 + 다시 계산"으로 캐시된 값임을 솔직하게 말한다.

## 헷갈리거나 불편한 점

1. **요약 줄 색과 행 색이 다르다(02, 03, 26, 27, 28).** 행은 빨간 "실패", "원본 없음"인데 요약은 주황색 "주의 1"이다. 실패·원본 없음은 주의가 아니라 오류다. 요약에서 심각도가 묻힌다.
2. **실패 행에서 시각이 잘린다(02, 26, 28).** "미러 · 업데이트 실패 · 네트워크 오류 · 방…" 처럼 가장 중요한 "언제부터"가 말줄임표로 사라진다. "미러 ·"를 빼거나 두 줄을 허용해야 한다.
3. **백그라운드 멈춤 상태가 과하게 시끄럽다(05).** 배터리 최적화 배너와 "백그라운드 확인이 멈춘 것 같아요" 배너가 위아래로 두 개 쌓이고, 모든 미러가 "지연"이 되어 칩이 "주의 필요 13"이 된다. 원인이 하나(백그라운드 중지)인데 13개 경고로 보인다. 원인이 공통이면 행 배지는 낮추고 배너 하나로 모으는 게 맞다. 그리고 이 상태에서는 원래 요약 줄이 사라진다.
4. **FAB이 마지막 행 내용을 가린다(04, 20, 21b, 26, 27, 28).** "1.1 MB", "10.1 KB", "3.0 KB"가 "레포 추가" 버튼 아래로 숨는다. 리스트 하단 패딩이 없거나, 스크롤 시 FAB을 축소하지 않는다.
5. **일괄 미러 하단 바가 목록을 자른다(24).** "hello-world" 행이 중간에서 잘린 채 고정 바와 겹친다. 그리고 GitHub 사용자/조직, GitLab 사용자/그룹을 필터 칩으로 단일 선택하게 한 건 패턴이 맞지 않는다. 단일 선택이면 세그먼트 버튼이나 드롭다운이 맞다.
6. **"탭하면 주소가 복사돼요"(14).** 복사 아이콘이 따로 있는데 행 전체 탭도 복사라고 하면, QR 버튼을 누르려다 복사가 되는지 헷갈린다. 아이콘이 있으면 설명은 빼도 된다.
7. **설정 순서(29).** "밖에서 접속하기 (ngrok)"가 "정보(버전, 라이선스)" 섹션 아래, 설정 맨 끝에 있다. 보안상 제일 중요한 설정이 앱 버전보다 아래 있는 건 이상하다. 서버 섹션 근처로 올려야 한다.
8. **확인 주기 대화상자의 "아래 스위치"(22).** 대화상자 안에서 "자동 업데이트 조건은 아래 스위치에서 바꿔요"라고 하는데, 그 아래는 대화상자 뒤에 가려져 있다. 그리고 요약 행이 "변경 확인: 6시간마다 · 자동 업데이트: 와이파이에서만"인데 대화상자에는 와이파이 조건이 없어서 어디서 바꾸는지 모른다.
9. **새 로컬 레포 시트에 뒤로 화살표와 드래그 핸들이 같이 있다(15).** 바텀시트인지 전체 화면인지 애매하다. 하나로 정해야 한다. 그리고 `git push -u phone main`은 기본 브랜치가 `master`인 오래된 레포에서 그대로 실패한다. 한 줄 언급이 있으면 좋겠다.
10. **알림 아이콘이 기본 안드로이드 로봇이다(17, 21, 30).** 앱 아이콘이 아니라 템플릿 아이콘이 그대로 나온다. 그리고 서버 알림이 "무음" 그룹에 있어서 ngrok 토큰 실패(30)를 알림으로는 알아차리기 어렵다.
11. **"히스토리 바뀜" 배지가 언제 사라지는지 모르겠다(12, 13, 14).** 상세 상단에 계속 붙어 있다. 확인하면 사라지는지, 다음 정상 업데이트 때 사라지는지 단서가 없다.
12. **저장 공간 막대(23).** 4.2 MB인데 상단 막대가 눈에 띄게 차 있다. 106 GB 대비라면 거의 0이어야 한다. 최소 너비를 준 거라면 의미 없는 막대라 빼는 게 낫다.

## 문구와 용어

- **"보존된 기록" vs "보존 기록"이 섞여 있다.** 06 "보존된 기록 보기", 07 제목 "design-tokens 보존 기록", 13 "보존된 기록 4개", 16 "보존 기록과 이력은 남아요", 웹 08 탭 "보존된 기록". 하나로 통일하자. 나는 짧은 "보존 기록"이 낫다.
- **"확인 주기" vs "변경 확인 주기" vs "변경 확인"(12, 13, 22).** 같은 개념에 세 이름이다.
- **자동 업데이트를 껐을 때 설명이 화면마다 다르다.** 13 "끄면 변경 확인만 하고 받지는 않아요", 22 "끄면 배지만 붙어요", 13 행 "자동 업데이트 꺼짐 · 확인만 해요". 같은 문장을 쓰자.
- **"push만"(19, 29b).** 버튼 이름만 보면 "push만 허용"으로 읽힌다. 실제 뜻은 "push할 때만 비밀번호 요구"다. 설명을 읽어야 이해된다. "push 때만" 정도면 오해가 줄어든다.
- **"연결되면 비밀번호 없이 공개돼요."(20, 29, 29b).** 무엇이 연결되면인지 빠져 있다. "ngrok이 연결되면"이라고 써야 29b처럼 ngrok 영역 밖에 나왔을 때도 통한다. 20에서는 앞 문장 "확인하세요"에 마침표가 없고 다음 줄은 있어서 문장 부호도 들쭉날쭉하다.
- **"새 브랜치·태그"(06).** 칩만 보면 feature/icons가 브랜치인지 태그인지 알 수 없다. 이미 ref 이름을 알고 있으니 "새 브랜치"와 "새 태그"로 나누면 된다. 반대로 "태그 이동됨"은 따로 있는데 "새 태그"가 없는 것도 비대칭이다.
- **"LFS 파일 없음"(11).** 헤더 배지만 보면 "이 레포는 LFS를 안 쓴다"로 읽힌다. 실제 뜻은 "LFS 파일은 저장 안 하고 포인터만 있음"이다. 정보 패널의 "LFS 파일 없음(포인터만)"이 맞는 표현이니 배지도 "LFS 포인터만"으로.
- **로컬 레포의 "받는 범위"(11).** 로컬 레포는 받는 쪽이 아니라 push받는 쪽이라 "받는 범위: push된 브랜치·태그"가 어색하다. 로컬에는 이 행이 필요 없다.
- **날짜 형식이 앱과 웹이 다르다.** 앱 07 "2026.10.25 16:35", 웹 08 "2026. 10. 25. 오후 4:35". 07 안에서도 "커밋 5일 전"과 "커밋 2026.10.12"가 섞여 있다(07). 보존 기록은 절대 시각이 맞다.
- **"주의 필요" 칩과 요약 "주의"**(01)는 맞는데, 이 안에 실패·원본 없음까지 들어가는 게 위 1번 문제와 연결된다. "확인 필요"처럼 중립적인 단어가 나을 수 있다.
- 06 요약의 "강제 push·삭제 감지: 3개 보존"은 줄바꿈이 "3 / 개 보존"으로 갈려 읽기 어렵다(아래 레이아웃 참고).

## 시각과 레이아웃 문제

- **요약 줄 줄바꿈이 "·"로 시작한다(04).** "미러 13개 · 정상 12 · 주의 1" 다음 줄이 "· 마지막 확인 1시간 전"으로 시작한다. 구분자가 줄 맨 앞에 오면 지저분하다. FlowRow로 항목 단위 줄바꿈을 하거나 구분자를 앞 항목에 붙여야 한다.
- **"주의 필요 13" 칩이 화면 끝에서 잘린다(05).** 가로 스크롤 칩 행인 건 알겠지만 숫자 끝이 잘리면 13인지 1인지 헷갈린다. 오른쪽 페이드나 패딩이 필요하다.
- **값 안의 숫자와 단위가 갈라진다.** 13 "확인만 해요 · 6 / 시간", 06 "감지: 3 / 개 보존", 07 "바꿀 수 없어 / 요." 한국어 줄바꿈이 글자 단위로 끊긴다. Compose라면 `TextStyle`의 `lineBreak`를 단어 단위로 바꿔 보고, 숫자와 단위는 NBSP로 묶으면 된다.
- **URL과 명령어 줄바꿈 위치(07, 10, 12, 15).** `git fetch` 명령이 `'refs/archive/` 중간에서 끊긴다(07). 복사 버튼이 있으니 읽기만 하면 되지만, 가로 스크롤 한 줄 코드 블록이 개발자에게는 더 익숙하다.
- **배지 크기가 들쭉날쭉(06).** 칩 길이가 텍스트에 따라 달라서 ref 이름 시작 위치가 줄마다 다르다. 칩 열 너비를 고정하거나 ref 이름을 위로 올리면 스캔하기 쉽다.
- **18 대화상자의 두 번째 버튼이 두 줄로 감긴다.** "비밀번호 요구를 "읽기·쓰기"로 바꾸고 공개"가 알약 버튼 안에서 줄바꿈되어 왼쪽 정렬처럼 보인다. 짧게 "읽기·쓰기로 바꾸고 공개"면 한 줄이다.
- **20 배너의 버튼 두 개 크기가 다르다.** "외부 공개 끄기"는 크고 굵게, "자세히"는 작게 따로 줄을 차지한다. 21b처럼 텍스트 버튼 하나 크기로 맞추고 가로로 놓으면 높이가 줄어든다.
- **배너 위계(01, 05, 20, 21b).** 정보성(파랑), 경고(주황), 오류(빨강) 배너가 모두 같은 크기와 위치로 서버 카드 위·아래를 오간다. 20, 21b는 서버 카드 위, 01은 아래다. 위치 규칙을 하나로 정하자.
- **13, 16의 "분리하기" 행.** 긴 설명 4줄 옆에 텍스트 버튼이 세로 가운데에 떠 있다. 설명 아래에 버튼을 두는 편이 Material 카드 패턴에 맞다.
- **15의 "Git LFS를 쓰는 프로젝트라면" 머리글이 회색이라 비활성처럼 보인다.** 펼침 영역 머리글은 본문과 같은 색이 낫다.
- **웹 10 오른쪽 패널**에 clone 주소, clone 명령, fetch 명령, 설명 두 단락이 몰려 있어 길다. 보존 기록 fetch 명령은 이미 보존 기록 탭(08)에 있으니 여기서는 링크만 둬도 충분하다.

## 가장 먼저 고칠 것 3가지

1. **메인 목록의 상태 정확도: 요약 색과 시각 잘림(02, 26, 28, 05).** 실패·원본 없음이 요약에서 주황 "주의"로 묻히고, 행에서는 "방…"으로 언제부터인지 잘린다. 백그라운드 멈춤 때는 원인 하나가 "주의 필요 13"으로 부풀려진다. 이 앱의 존재 이유가 "원본 변화를 믿고 맡기는 것"이라 메인 상태가 정확하고 읽혀야 한다. 요약에 오류 수를 빨강으로 따로 세고, 행 부제에서 "미러 ·"를 빼 시각을 살리고, 공통 원인은 배너 하나로 모으자.
2. **목록이 가려지는 레이아웃(04, 20, 21b, 24, 26~28).** FAB과 일괄 미러 하단 바가 마지막 행 정보를 가린다. 리스트 `contentPadding` 하단에 FAB 높이만큼 여백을 주고, 스크롤 시 확장형 FAB을 아이콘만 남기게 줄이면 끝난다. 작은 수정으로 체감이 크다.
3. **용어 통일: 보존 기록, 확인 주기, 자동 업데이트 끔, push만, "연결되면"(06, 07, 13, 19, 20, 22, 29b).** 같은 개념에 이름이 두세 개라 처음 쓰는 사람은 다른 기능으로 오해한다. 문자열 리소스에서 한 번 정리하면 앱과 웹이 같이 맞춰진다. 특히 "push만"과 "연결되면 비밀번호 없이 공개돼요"는 보안 설정이라 오해 비용이 크다.

그 다음 순위로는 알림 아이콘(17, 21, 30)을 앱 아이콘으로 바꾸는 것을 넣고 싶다. 사소하지만 알림창에서 "미완성 앱"처럼 보이는 가장 큰 원인이다.
