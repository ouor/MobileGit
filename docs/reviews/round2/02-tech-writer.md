# 2차 리뷰 — 테크니컬 라이터 (경력 9년)

- 리뷰어: 개발자 문서를 쓰는 테크니컬 라이터. git은 clone, pull, push, commit 정도만 손에 익음. force-push, refs, LFS는 "들어는 봤다" 수준.
- 보는 눈: 문구 일관성, 오해 소지, 초보자가 이해할 수 있는지.
- 근거: `docs/qa/round2/screenshots/` 30장(01~30, 21b, 29b 포함)과 같은 폴더 README.md. 화면 번호는 파일명 앞 번호.

## 1. 첫인상

말투는 처음부터 끝까지 "~해요"체로 맞춰져 있고, 문장이 짧고 능동형입니다. 개발자 도구에서 이런 톤을 끝까지 지키는 경우는 드문데, 문서 쓰는 사람으로서 반가웠습니다. 위험한 동작에는 거의 다 "왜 위험한지"가 한 문장씩 붙어 있습니다. 예를 들어 14의 "같은 와이파이의 다른 기기가 비밀번호를 엿볼 수 있어요.", 18의 "주소를 아는 인터넷의 누구나 레포를 읽을 수 있어요."가 그렇습니다.

반대로 **같은 개념을 화면마다 다른 이름으로 부르는 문제**가 눈에 많이 띕니다. "보존된 기록 / 보존 기록", "외부 공개 / 외부 접속 / 밖에서 접속하기", "백업 / 내보내기", "미러 / 사본 / 복제본"이 대표적입니다. 문장 하나하나는 좋은데, 모아 보면 용어집 없이 쓴 문서처럼 읽힙니다. git을 잘 모르는 사람은 이름이 다르면 다른 기능이라고 받아들입니다.

## 2. 좋은 점

1. **상태 문구가 사람 말이다.** 04 "6시간 주기인데 3일째 확인 못 함"은 "지연"이라는 배지보다 훨씬 많은 걸 알려 줍니다. 무엇을 기대했고 실제로는 어땠는지가 한 줄에 다 들어 있습니다. 이 앱에서 가장 잘 쓴 문구라고 생각합니다.
2. **"남는 것 / 바뀌는 것" 구조(16).** 결정을 앞둔 사용자에게 딱 맞는 틀입니다. 아래쪽 "원본으로 다시 보내려면 분리한 레포를 PC에서 clone한 뒤 원본에 push하세요. 앱이 원본으로 보내지는 않아요."는 사용자가 오해할 만한 지점을 미리 막아 줍니다.
3. **계정 안내가 정확하다(12, 15).** "사용자 이름에 git, 비밀번호에 이 앱의 비밀번호를 넣으세요. GitHub 계정이 아니에요." 초보자가 가장 많이 막히는 지점을 정확히 짚었습니다. 15의 "비밀번호를 모르면 설정에서 다시 정할 수 있어요."로 이어지는 흐름도 좋습니다.
4. **연결 경로별 보안 표(19, 29b).** 와이파이·Tailscale·ngrok을 색 점과 한 줄 설명으로 비교해서, 문서로 치면 "비교표 한 장"이 해야 할 일을 해냅니다.
5. **명령어 옆에 맥락이 있다.** 07 "보존 기록은 일반 clone에 들어가지 않아요. 받은 레포에서 아래 명령을 실행하세요."처럼 명령만 던지지 않고 "왜, 어디서"를 먼저 말합니다. 15의 VS Code 메뉴 경로("소스 제어 ··· 메뉴 › 원격 › 원격 추가")는 터미널을 안 쓰는 사람까지 챙긴 배려입니다.
6. **재시작 알림의 정직함(21, 21b).** "외부 공개는 꺼진 채로 다시 시작했어요"는 사용자가 묻기 전에 상태 변화를 먼저 알려 줍니다.
7. **웹 하단 한 줄(08, 10, 11).** "웹에서는 보기만 할 수 있어요. 미러 업데이트와 레포 관리는 폰 앱에서, push는 PC의 git으로 해요." 세 갈래 역할 분담을 한 문장에 정리했습니다.

## 3. 헷갈리거나 불편한 점

1. **"push만"이 거꾸로 읽힌다(19, 29b, 18, 25).** 비밀번호 요구의 세 버튼 "읽기·쓰기 / push만 / 끄기" 중 "push만"을 처음 보면 "push만 허용"으로 읽힙니다. 실제 뜻은 "push할 때만 비밀번호를 요구"입니다. 설명문("clone과 웹 화면은 비밀번호 없이 열려요")을 읽어야 비로소 이해가 됩니다. 보안 설정에서 버튼 이름만 보고 반대로 이해할 수 있다는 건 위험합니다. "읽기·쓰기"도 같은 문제입니다. 무엇이 읽기·쓰기라는 건지(권한인지, 비밀번호를 요구하는 범위인지) 드러나지 않습니다.
2. **"연결되면 비밀번호 없이 공개돼요."의 주어가 없다(20, 29, 29b).** 무엇이 연결되는지(ngrok 터널), 무엇이 공개되는지(clone과 웹 화면, push는 아님)가 빠져 있습니다. 29b에서는 이 문장이 ngrok 영역이 아니라 "비밀번호 요구" 아래에 나와서, ngrok과 관계있다는 사실조차 알기 어렵습니다. 경고 문구일수록 주어와 범위를 생략하면 안 됩니다.
3. **20의 배너는 메시지 두 개가 한 칸에 섞여 있다.** 제목은 "외부 공개 실패 (ngrok)"인데 마지막 줄은 "연결되면 비밀번호 없이 공개돼요."입니다. 실패했다는 소식과 앞으로 생길 위험을 같은 빨간 상자에 이어 쓰니, "실패했으니 안전하다"로 읽어야 할지 "위험하다"로 읽어야 할지 헷갈립니다. 첫 문장은 마침표 없이 끝나고 둘째 문장에만 마침표가 있어서, 두 문장이 다른 곳에서 붙여 넣은 문장처럼 보입니다.
4. **설정 화면 안에서 "설정에서 ~하세요"(29).** 외부 접속 토글 아래에 "ngrok이 토큰을 거부했어요. 설정에서 authtoken을 확인하세요"라고 나오는데, 사용자는 이미 설정 화면에 있습니다. 바로 아래 줄이 authtoken 항목이니 "아래 authtoken을 확인하세요"가 맞습니다.
5. **"마지막 업데이트"와 "마지막 확인"의 차이를 설명하지 않는다(01, 12, 13).** 메인 요약은 "마지막 확인 방금", 상세는 "마지막 업데이트 1분 전"입니다. 13처럼 자동 업데이트를 끈 미러에서는 "확인"과 "업데이트"가 정말로 다른 일인데, 두 낱말을 구분해 주는 곳이 없습니다. 22의 "바뀐 게 있는지만 봐서 데이터가 적게 들어요"가 유일한 힌트인데, 설정 깊숙한 곳에 있습니다.
6. **분리 시트의 "이력"이 무엇인지 모르겠다(16).** "보존 기록과 이력은 남아요."에서 "이력"이 06의 "동기화 이력"인지 커밋 히스토리인지 알 수 없습니다. "히스토리 바뀜"이라는 배지가 따로 있어서 더 헷갈립니다.
7. **"분리"인데 첫 번째 선택지는 분리가 아니다(13, 16).** 시트 제목은 "로컬 레포로 분리"인데 권장안은 "새 로컬 레포로 복제"입니다. 미러는 그대로 남으니 엄밀히는 분리가 아니라 복사입니다. 13 버튼 "분리하기"를 누른 사용자는 미러가 사라질 거라고 예상할 수 있습니다.
8. **"되돌릴 수 없어요."가 문단 속에 묻혀 있다(16).** 이 앱에서 가장 무거운 경고 가운데 하나인데, "바뀌는 것" 칸 본문 끝에 일반 글씨로 붙어 있습니다.
9. **변경 확인 주기 대화상자의 "아래 스위치"(22).** "자동 업데이트 조건은 아래 스위치에서 바꿔요."라고 쓰여 있지만, 대화상자가 그 스위치를 가리고 있습니다. 게다가 조건이 "와이파이에서만"이라는 사실은 요약 줄에만 있고, 스위치 자체는 켜기/끄기뿐이라 "조건"을 바꿀 곳이 보이지 않습니다.
10. **같은 기능을 두 번 다르게 설명한다(13, 22).** 미러별 자동 업데이트(13)는 "끄면 변경 확인만 하고 받지는 않아요", 전체 설정(22)은 "변경이 있으면 이어서 받아요. 끄면 배지만 붙어요"입니다. 둘 다 맞는 말이지만, 같은 스위치 이름 밑의 설명은 한 가지로 맞추는 게 좋습니다. 13과 22가 각각 어디에 적용되는지(이 미러만인지, 기본값인지)도 문구로는 알 수 없습니다.
11. **"방금"이 상황마다 뜻이 다르다(01, 03, 23).** "방금 보존", "방금부터", "방금 기준이에요"가 함께 나옵니다. 23의 "레포 용량은 방금 기준이에요"는 문장이 어색하고, 나중에 다시 보면 "방금"이 언제인지 알 수 없습니다. "1분 전에 계산했어요"처럼 시점을 적는 편이 낫습니다.
12. **21b 본문이 실제 상황과 다르다.** 강제 종료 뒤 다시 실행한 상황인데, 본문은 "폰이 다시 켜지거나 앱이 업데이트되면 외부 공개는 켜지지 않아요."입니다. 방금 겪은 일(앱이 종료됐다가 다시 열림)은 목록에 없어서 "그럼 지금은 왜 꺼졌지?"라는 질문이 남습니다.

### 4-2. 앱과 웹 사이 불일치

- **보존 기록 제목**: 앱 07 "design-tokens 보존 기록" / 웹 08 탭 "보존된 기록".
- **날짜 형식**: 앱 07 "2026.10.25 16:35", "커밋 2026.10.12" / 웹 08 "2026. 10. 25. 오후 4:35", "2026. 10. 12. 오후 4:40". 같은 시각을 24시간제와 오전·오후로 다르게 씁니다. 07은 한 카드 안에서도 "커밋 2026.10.12"와 "커밋 5일 전"이 섞여 있습니다(같은 종류의 정보인데 하나는 날짜, 하나는 상대 시간).
- **설명 길이**: 웹 08·09는 "실행하면 refs/archive/ 아래로 받아져요"까지 알려 주는데, 앱 07은 받은 뒤 어디에 생기는지 말하지 않습니다. 반대로 앱 07의 "보존 기록(refs/archive)은 push로 만들거나 바꿀 수 없어요."는 웹에 없습니다.
- **탭 구성**: 앱 상세는 "정보 / 동기화 이력", 웹은 "코드 / 커밋 / 보존된 기록"입니다. 플랫폼마다 역할이 다르니 탭이 달라도 괜찮지만, 앱에서 "동기화 이력"의 "보존된 기록 보기"(06)로 들어간 화면 제목이 "보존 기록"(07)인 건 고쳐야 합니다.
- **"PC로 받기" vs "PC에서 clone"**: 같은 웹 화면에 "PC에서 clone"(10, 사이드바)과 "PC로 받기"(08, 보존 기록 탭)가 같이 있습니다. 10 사이드바의 fetch 명령 블록에는 제목이 없어서 clone 명령의 연장처럼 보입니다.
- **LFS 표현이 한 화면에 세 번, 세 가지 말로(11)**: 상단 배지 "LFS 파일 없음", 경고 "LFS 파일은 저장되지 않아요 … 포인터 파일만 보존해요", 정보 패널 "LFS 파일 저장 안 함"과 "LFS 파일 없음(포인터만)". 특히 배지 "LFS 파일 없음"은 "이 레포에는 LFS 파일이 하나도 없다"로 읽힐 수 있습니다. 실제 뜻은 "LFS를 쓰지만 실제 파일은 여기 없다"입니다. 또 "보존해요"는 "보존된 기록"과 같은 낱말이라 다른 기능처럼 겹쳐 보입니다.
- **"받는 범위"(10, 11, 12)**: 미러에는 맞는 말이지만 로컬 레포(11)에도 "받는 범위: push된 브랜치·태그"로 나옵니다. 로컬 레포는 받는 게 아니라 push를 받는 쪽이라 문장이 어색합니다.
- **"보관된 레포 숨기기"(24)**: GitHub의 archived를 "보관된"으로 옮겼는데, 앱의 핵심 기능 "보존된 기록"과 한 글자 차이입니다. 초보자는 같은 개념으로 착각하기 쉽습니다. "아카이브된 레포 숨기기" 또는 "GitHub에서 보관 처리된 레포 숨기기"를 권합니다.

### 4-3. 경고 문구가 명확한가

### 4-4. 표기·문장부호

- 설명문 끝 마침표가 제각각입니다. 19 "…비밀번호가 필요해요"(없음), 바로 아래 29b 빨간 줄 "…공개돼요."(있음). 22 "…주기를 바꿔요"(없음)와 대화상자 "…바꿔요."(있음). 항목 보조 설명은 마침표 없이, 독립된 문단은 마침표를 찍는 식으로 규칙을 하나 정하세요.
- 06 "강제 push·삭제 감지: 3개 보존"은 가운뎃점·콜론·숫자가 몰려 있어 끊어 읽기 어렵습니다. "강제 push나 삭제로 3개를 보존했어요"가 낫습니다. 같은 줄의 "브랜치·태그 5개 변경"은 브랜치 5개인지 합쳐서 5개인지 애매합니다.
- 06 변화 종류 "새 브랜치·태그"는 해당 행(feature/icons)이 브랜치인지 태그인지 알려 주지 않습니다. 이웃 배지들("브랜치 삭제됨", "태그 이동됨")은 하나만 가리키는데 이것만 둘 다를 가리킵니다.
- 12·13 "다음 확인 약 22:45 이후"는 "약"과 "이후"가 겹쳐 흐릿합니다. "다음 확인 22:45쯤"이면 충분합니다.
- 19·29b "폰 안(127.0.0.1)"은 초보자에게 낯선 표현입니다. 127.0.0.1이 무엇인지 모르는 사람에게는 괄호가 설명이 아니라 짐입니다. "폰 안에서 접속할 때"로 쓰거나 괄호를 빼세요.
- 15 "코드와 LFS 포인터만 올라가요"의 "LFS 포인터"는 이 앱에서 끝까지 설명되지 않습니다. "큰 파일은 빠지고, 그 파일을 가리키는 작은 표시 파일만 올라가요" 정도의 풀이가 한 번은 필요합니다.

## 5. 시각과 레이아웃 문제

1. **상태 문구가 잘린다(02, 26, 28).** "미러 · 업데이트 실패 · 네트워크 오류 · 방…" 가장 중요한 실패 행에서 "언제부터"가 잘립니다. 실패 배지가 아래에 따로 있으니 줄 안의 "업데이트 실패"를 빼거나 "· 방금부터"를 줄여야 합니다. 03 "원본 없음 · 방금부터"는 잘리지 않는 걸 보면 문구 길이 문제입니다.
2. **요약 줄이 가운뎃점으로 시작하며 꺾인다(04).** 둘째 줄이 "· 마지막 확인 1시간 전 · 로컬 3개"로 시작합니다. 줄바꿈 지점을 가운뎃점 뒤로 옮기거나 두 덩어리로 나눠야 합니다.
3. **낱말 중간이나 마지막 한 글자에서 줄이 꺾인다.** 13 "· 6 / 시간 ·", 07 "바꿀 수 없어 / 요.", 13 "만들 수 있어 / 요.", 16 "따라가 / 요.", 22 "배지만 붙어 / 요", 01 "자동 업데이트 / 가 멈출". 한국어 어절 단위 줄바꿈(word-break: keep-all에 해당하는 설정)이 앱 전반에 빠져 있는 것 같습니다. 웹 09("지워지지 않아 / 요.")도 같습니다.
4. **노란 상자가 두 개 겹친다(05).** "배터리 최적화를 꺼 주세요"와 "백그라운드 확인이 멈춘 것 같아요"가 같은 색, 같은 모양으로 쌓여 있습니다. 둘은 원인과 결과 관계인데 따로 놀고, 버튼도 "설정하기"와 "배터리 안내"로 이름이 다릅니다. 하나로 합치는 게 맞습니다. 이 상태에서는 요약 줄("미러 13개 · …")이 사라지고 칩만 "주의 필요 13"으로 바뀌는데, 칩 끝이 화면 밖으로 잘려 숫자를 읽기 어렵습니다.
5. **FAB가 행 내용을 가린다(01~05, 14, 20, 21b, 26~28).** "레포 추가" 버튼이 마지막 보이는 행의 크기·시각 정보를 덮습니다("1.", "3.0 K"). 목록 아래 여백이 필요합니다.
6. **보존 기록 화면 위계(07).** 커밋 메시지("다크 모드 배경색 초안")가 큰 검은 글씨이고 브랜치명이 배지 옆에 붙어 있어서, 첫눈에 무엇이 제목인지 헷갈립니다. 웹 09의 "브랜치명 + 배지 → SHA → 커밋 메시지 → 날짜 → 지금 원본" 순서가 더 잘 읽힙니다.
7. **알림 아이콘이 기본 안드로이드 로고(17, 21, 30).** 문구와는 별개로, 앱 정체성이 드러나지 않아 다른 앱 알림처럼 보입니다. 17은 "qa 폴더에 mobilegit-backu…"로 잘려서 펼치지 않으면 파일 이름을 볼 수 없습니다.
8. **위험 버튼 배치(18, 25).** 가장 안전한 "취소"가 가장 진한 파란 버튼이라는 점은 좋습니다. 다만 18의 가운데 버튼이 두 줄로 꺾여서 세 버튼의 높이가 다 다릅니다.
9. **웹 정보 패널 숫자(10, 11).** "브랜치 · 태그 3 · 2"는 무엇이 3이고 무엇이 2인지 줄을 따라가야 압니다. "브랜치 3 · 태그 2"가 낫습니다.
10. **20 배너의 버튼 두 개.** "외부 공개 끄기"(굵게)와 "자세히"(작게)가 위아래로 놓여 있고, 둘 다 같은 빨간색이라 무엇이 주된 행동인지 흐립니다.

## 6. 가장 먼저 고칠 것 3가지

1. **용어집을 하나 만들고 앱·웹 전체에 적용하기.** 최소한 다음 네 쌍을 통일하세요. "보존된 기록 / 보존 기록", "외부 공개 / 외부 접속 / 밖에서 접속하기", "전체 백업 / 내보내기", "미러 / 사본 / 복제본". 날짜 형식도 함께 정하고(07 vs 08), "보관된 레포"(24)처럼 핵심 용어와 헷갈리는 낱말은 바꾸세요. 개별 문장은 이미 좋기 때문에, 이것만 해도 체감 품질이 가장 크게 오릅니다.
2. **보안 관련 문구를 결과 중심으로 다시 쓰기.** "push만 / 읽기·쓰기 / 끄기"를 "push할 때만 / 항상 / 안 함"처럼 *비밀번호를 언제 묻는지*로 바꾸세요(19, 29b). "연결되면 비밀번호 없이 공개돼요."에 주어와 범위를 넣으세요(20, 29, 29b). "그래도 진행"은 결과를 적은 버튼으로 바꾸세요(18, 25). 25의 제목은 실제 상황("비밀번호 설정을 바꾸면 외부 공개가 비밀번호 없이 열려요")에 맞게 따로 쓰세요. 사용자가 잘못 읽었을 때 결과가 가장 나쁜 곳이 여기입니다.
3. **잘림과 줄바꿈 정리.** 실패 행의 "방…" 잘림(02, 26, 28), 요약 줄의 가운뎃점 줄 시작(04), "요." 한 글자 줄바꿈(07, 13, 16, 22 외)을 고치세요. 어절 단위 줄바꿈 설정 하나로 상당 부분이 해결될 것 같습니다. 05의 노란 상자 두 개도 하나로 합치세요.
